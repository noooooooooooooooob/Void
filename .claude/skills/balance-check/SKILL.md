# 밸런스 점검

## 데이터가 없으면 "점검 불가"가 답이다
보고서를 만들기 전에 먼저 확인한다.
1. 이 점검이 읽을 입력(아래 Phase 2) 목록을 만들고 각각 `있음` / `없음` 을 적는다.
2. 필요한 입력이 없는 항목은 **`점검 안 됨 — 데이터 없음`** 으로 둔다. 추정하거나 옆 자료로 대신하지 않는다.
3. 모든 입력이 없으면 그 자체를 결론으로 보고하고 멈춘다.

**"점검 안 됨"은 실패가 아니라 정확한 답이다.** 기준값이 없는데 "건강함"이라고 쓰는 게 실패다.

## Phase 1: 범위 정하기
`$ARGUMENTS` 전체 문자열로 판단 (덱 이름에 공백이 있을 수 있음):
- **덱 이름** (예: `불씨 무녀`, `common`) → `cards/data/<덱>/*.tres`
- `cards` → 모든 덱
- `units` → `entities/units/*.tres`
- `statuses` → `statuses/data/*.tres`
- `equipment` → `statuses/equipment/*.tres`
- **파일 경로** → 그 파일만 읽고 종류를 내용으로 판단
- 인자 없음 → 무엇을 볼지 질문

## Phase 2: 데이터 읽기
- 해당 `.tres` 를 읽는다. 카드는 SP 비용(costs), 효과(effects: 종류·%·대상), 공격 종류(근접/원거리/아군/자신), 광역 오프셋, 분류, 키워드를 뽑는다.
- 수치 해석에 필요한 스크립트(`Scripts/cards/`, `Scripts/battle/`)는 필요한 부분만 읽는다.
- 읽은 파일은 전부 보고서 "데이터 출처"에 적는다.
- **적 전용(검정)** 카드는 플레이어 카드와 따로 본다 (플레이어 덱·보상·상점에 안 나옴).

## Phase 3: 기준값 찾기
우선순위:
1. 사용자가 이번에 알려준 목표값
2. `docs/balance/targets.md` (있으면)
3. 설계 스펙 `docs/superpowers/specs/*` 의 수치
4. Notion 카드 페이지 / "구현 확정" (도구가 있으면 조회)

확정 규칙 (CLAUDE.md):
- 수치 = 스탯 × % (내림, 최소 1). 피해·회복은 공격 스탯, 방어도는 방어 스탯 기준
- 방어 스탯은 받는 피해를 줄이지 않음 (방어도 계수용)
- 치명타는 피해 효과에만, 대상마다 개별 판정
- 근접은 같은 행 맨 앞 적 자동 지정, 없으면 사용 불가

기준값이 하나도 없으면 "튀는 수치" 항목은 `점검 안 됨 — 데이터 없음` 으로 두고, 기준값을 `docs/balance/targets.md` 에 정하자고 제안한다.

## Phase 4: 분석
**공통**: 기준이 있는 값은 기준과 비교. 기준이 없는 값은 "기준 없음 — 판단 안 함" 으로 따로 적는다.

**카드**
- SP 1당 효율: (효과 % 합 × 대상 수) / SP. 같은 분류·공격 종류끼리 비교해 튀는 카드 찾기
- 다른 카드보다 모든 면에서 나은(완전 상위호환) 카드
- 쓸 이유가 없는 카드 (완전 하위호환)
- 광역 오프셋이 넓은데 % 가 낮지 않은 카드
- 근접 카드가 쓸 수 없는 상황이 잦은지 (격자 기준)
- SP 0 이거나 SP 를 돌려받는 카드 → 무한 연쇄 가능성
- 키워드 상호작용으로 생기는 무한 루프·필승 조합

**유닛 / 상태 / 장비**
- 대표 유닛 스탯으로 실제 피해·방어도 수치 계산 → 적 HP 대비 몇 턴에 쓰러지는지
- 방어도가 매 턴 들어오는 피해를 항상 넘는 "안 죽는 상태"
- 상태 중첩이 끝없이 커지는지, 장비 공격 보너스가 너무 큰지

## Phase 5: 보고서
```
## 밸런스 점검: [범위]

### 데이터 출처
- [읽은 파일]

### 종합: [점검 안 됨 / 건강함 / 우려 / 심각]

### 튀는 수치
| 항목 | 기준 | 실제 | 문제 |
|------|------|------|------|

### 압도적 전략 / 무한 루프
- [설명과 왜 문제인지]

### 권장 수정
| 우선순위 | 문제 | 수정안 | 영향 |
|---------|------|--------|------|

### 살펴볼 값
[구체 값, 제안 수치, 이유. 기준 없음 항목도 여기]
```
종합 판정 (가장 나쁜 것 기준, 위에서부터):
- **심각** — 다른 선택을 전부 압도하는 카드·조합, 무한 루프, 안 죽는 상태
- **우려** — 수치 조정으로 고칠 수 있는 튀는 값
- **점검 안 됨** — 데이터·기준이 없어 판단 못 한 부분이 있음 (무엇이 없는지 명시)
- **건강함** — 모든 값이 기준과 비교됐고 문제 없음

## Phase 6: 다음 행동
`AskUserQuestion` 으로:
- `[A] 가장 급한 문제부터 같이 고치기`
- `[B] 보고서를 docs/balance/balance-check-[범위]-[YYYY-MM-DD].md 에 저장`
- `[C] 여기서 멈춤`

[A] 일 때:
- 카드 수치 중 **웹 에디터 칸**이면 웹 카드 에디터에서 고치고 다시 가져오라고 안내한다 (`.tres` 를 직접 고치면 다음 가져오기에 덮어써짐).
- effects/costs/conditions 등 Godot 쪽 값은 **에디터 인스펙터**에서 고치도록 안내하거나, 에디터가 켜져 있으면 MCP 로 고친다. 에디터가 켜진 상태에서 바깥에서 `.tres` 를 쓰지 않는다.
- 고친 뒤 이 점검을 다시 돌릴지 묻는다.
