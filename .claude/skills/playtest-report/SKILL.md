# 플레이테스트 보고서

## Phase 1: 모드
- `new` → 빈 양식 출력 후 끝 (저장 안 함)
- `analyze [경로]` → 메모를 읽어 양식을 채움. 경로 대신 대화에 붙여넣은 메모도 가능
- 인자 없음 → `AskUserQuestion`: `[A] 빈 양식` / `[B] 메모 정리 — 경로나 내용을 줄게`

## Phase 2B: 메모 정리
- 메모를 읽고 양식을 채운다.
- 관련 설계 스펙(`docs/superpowers/specs/`)·CLAUDE.md 의 확정 규칙과 비교해, **기획 의도와 다르게 느껴진 부분**을 표시한다. 문서는 제목(`^#`)으로 필요한 부분만 찾아 읽는다.
- 크래시, 진행 불가, 명백히 고장난 동작은 "불편했던 점"이 아니라 **버그 표**로. 불편했던 점은 "플레이 느낌" 문제만.

## Phase 3: 분류와 다음 행동
발견을 네 갈래로 나눠 보여준다:
- **기획 변경** — 재미·이해 문제, 기획 의도와 어긋남 → Notion "구현 확정"/스펙을 고칠지 팀 논의. 코드 변경이면 superpowers:brainstorming 부터
- **밸런스 조정** — 수치가 이상함 → `/balance-check [범위]`
- **버그** — 재현되는 구현 결함 → `docs/bugs/` 에 버그 보고서 작성 (`/bug-triage` 의 양식), 고칠 땐 superpowers:systematic-debugging
- **다듬기** — 막히진 않지만 거슬림 → `docs/progress.md` 의 할 일에 추가 제안

## Phase 4: 저장
"`docs/playtests/playtest-[YYYY-MM-DD]-[테스터].md` 에 저장할까요?" 라고 묻고, 예면 저장 (폴더 없으면 만듦).
