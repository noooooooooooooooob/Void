# 소비 아이템 — 가방, 전투 중 사용, 전투 드랍 (설계)

날짜: 2026-11-17 · 상태: 승인 (2026-11-17, 범위 축소 반영)

> 대상(아군 한 명 → 아군/적/둘 다 + 범위), 수치 0 이상 → 음수 가능, 가져오기는 `2026-11-17-consumable-targets-design.md` 로 대체됨.

## 왜

스테이지 하나를 규칙대로 끝까지 진행하게 만드는 중이다. 노션 의뢰 페이지의 전투 보상(카드 / 공허 내 재화 / 사용 아이템) 중
**사용 아이템**부터 넣는다. 아이템을 만드는 곳(웹 카드 에디터의 소비 아이템 탭)은 2026-11-16 에 생겼고,
Godot 쪽에는 데이터도 쓰는 방법도 아직 없다.

## 사용자가 정한 것 (2026-11-17)

- 가방은 **파티 공용 인벤토리** 하나, **5칸**
- 사용에 **비용 없음** (SP·행동을 쓰지 않음)
- 사용 시점: **아군 차례의 카드 사용 페이즈에만** (드로우·대기 페이즈 뒤 ~ 차례 종료 전). 적 차례·연출 중에는 못 씀
- 가방은 평소 닫혀 있고 **TAB 키 또는 화면의 버튼**으로 연다
- 얻는 길: **전투 승리 시 확률 드랍** + 상점 구매. 드랍 확률은 **전투 공통 값 하나**, 처음 값 **40%**
- **이번에는 시험판**: HP 회복·SP 회복 아이템만 넣는다. 스탯 버프는 다음에
- **SP 회복은 최대 SP 를 넘어도 된다**

## 목표

1. 시험용 소비 아이템 2개(HP 회복약, SP 회복약)가 Godot 데이터로 있다
2. 의뢰 동안 유지되는 5칸 가방이 있다
3. 전투 중 가방을 열어 아이템을 아군 한 명에게 쓸 수 있다
4. 의뢰의 일반 전투에서 이기면 40% 확률로 무작위 아이템 1개가 나온다

## 하지 않는 것

- **스탯 버프 아이템** (사용자 결정: 이번엔 HP·SP 회복만). 효과 줄 종류에 자리만 두지 않고 아예 넣지 않는다 — 넣을 때 추가
- **웹 에디터 → Godot 가져오기** — 시험 아이템은 Godot 에서 직접 만든다. 가져오기는 버프와 함께 다음 단계 (아래 "다음 단계" 참고)
- 상점 구매, 재화(공허 조각), 카드 보상 — 재화를 만들 때 같이
- 의뢰 밖(사무소)에서도 남는 인벤토리 — 사무소 화면이 생길 때. 이번 가방은 의뢰 시작 때 비어 있고 의뢰가 끝나면 사라진다
- 지도·방 화면에서 아이템 사용 (사용 시점은 전투의 카드 사용 페이즈뿐)
- 적의 아이템 사용, 죽은 아군 되살리기
- Godot → 웹 방향 내보내기에 소비 아이템 넣기
- 아이템 전용 연출 씬

## 실패로 보는 것

- 아이템을 넣으면서 카드 사용·차례 진행·연출 순서가 달라짐
- `consumables` 키가 없는 예전 zip 을 가져올 때 오류가 나거나 기존 아이템 파일이 지워짐
- 같은 시드의 전투 결과가 드랍 판정 때문에 달라짐 (드랍 난수는 전투 난수와 따로)

## 접근

- **채택: 소비 아이템을 따로 된 리소스(`ConsumableData`)로 두고, 웹 에디터의 효과 줄을 전투가 직접 해석한다.**
  웹 형식(HP 회복 / SP 회복 / 스탯 버프)과 1:1 이라 가져오기가 단순하고, 장비와 같은 분담(웹 칸은 덮어쓰고 Godot 칸은 유지)이 그대로 이어진다.
  특수 효과용으로 Godot 담당 칸 `effects`(카드와 같은 효과 부품)를 하나 둔다.
- 기각: 아이템을 카드로 만들기 (`CardData` 에 분류 추가) — SP·덱·손패·범위 규칙이 딸려 오고, 회복 기준이 다르다
  (카드 회복은 공격 스탯 × %, 아이템은 고정값 / 최대치의 %).
- 기각: 가져오기가 효과 줄을 카드 효과 부품(`CardEffect`)으로 바꿔 저장 — 고정 회복·SP 회복·기한 있는 버프 부품을 새로 만들어야 해서
  이득이 없고, 다시 가져올 때 "웹이 만든 부품"과 "Godot 에서 붙인 부품"을 구분해야 한다.

## 데이터

### `ConsumableData` (`Scripts/items/consumable_data.gd`, 데이터는 `items/consumables/<이름>.tres`)

| 칸 | 담당 | 내용 |
|---|---|---|
| `id` | 웹 | 웹 에디터의 아이템 id. 시험 아이템은 비워 둔다 |
| `display_name`, `name_en`, `description_ko`, `description_en` | 웹 | 이름·설명 |
| `keywords` | 웹 | 키워드 id 목록 (카드와 같은 `cards/keywords/`) |
| `art` | 웹 | 그림 경로 (`items/consumables/art/…`) |
| `lines: Array[ConsumableLine]` | 웹 | 효과 줄. 위에서부터 차례로 적용 |
| `effects: Array[CardEffect]` | Godot | 특수 효과. `lines` 뒤에 실행. 가져오기가 건드리지 않는다 |

### `ConsumableLine` (`Scripts/items/consumable_line.gd`)

- `type`: `HEAL_HP` / `HEAL_SP`
- `kind`: `FLAT` / `PERCENT`
- `amount: int` (0 이상)

### 시험 아이템 (`items/consumables/`)

- `hp_potion.tres` — 회복약: HP 회복 +30 (고정)
- `sp_potion.tres` — 기력약: SP 회복 +2 (고정)

id 는 비워 둔다 (나중에 가져오기가 생겨도 id 없는 파일은 건드리지 않는다).

### 다음 단계: 가져오기 (이번엔 만들지 않음)

`addons/card_importer/consumable_importer.gd` 를 `EquipmentImporter` 와 같은 규칙으로 만든다: 웹 칸만 덮어쓰고 `effects` 유지,
파일 안의 id 로 찾아 이름이 바뀌면 옮김, zip 에 없는 파일은 저장보다 먼저 지움, `consumables` 키가 없으면 그대로,
id 없는 파일은 건드리지 않음, 그림은 `items/consumables/art/`.

## 규칙

### 사용 (`Battle.use_item(item, target)` — 순수 로직)

- 쓸 수 있는 조건: 대상이 **살아 있는 아군**. (시점 조건은 세션이 본다)
- 효과 줄을 위에서부터:
  - **HP 회복**: 고정값 또는 대상 최대 HP 의 % (내림, 최소 1) → `Battle.heal` (최대 HP 를 넘지 않음)
  - **SP 회복**: 고정값 또는 대상 최대 SP 의 % (내림, 최소 1). **최대 SP 를 넘어도 된다** (사용자 결정). 넘친 SP 는 그 캐릭터의 다음 차례 시작에 최대 SP 로 돌아간다 (차례 시작의 SP 가득 회복 규칙 그대로)
- 그다음 `effects` 를 실행 (행위자 = 없음, 주인 = 대상, 대상 목록 = [대상], 출처 = 아이템)
- 새 이벤트 `ITEM_USED` (대상, 출처 = 아이템) 발행 — 전투 기록·화면 갱신용. 이벤트 enum 맨 뒤에 추가
- 아이템으로 생긴 회복은 "아무도 준 것이 아님" (상태로 생긴 효과와 같은 취급: 스태미너 회복·치명 없음)

### 가방 (`Scripts/items/inventory.gd`, 순수 로직)

- 칸 5개 (`CAPACITY`). `add(item) -> bool`(꽉 차면 false), `remove_at(i)`, `replace(i, item)`, `is_full()`, `items`
- `StageRun` 이 의뢰마다 하나 갖는다 (`start_run` 에서 새로, `end_run` 에서 비움)
- 전투 화면을 F6 으로 따로 열 때는 화면의 `@export var test_items` 로 채운 임시 가방을 쓴다 (시험용)

### 세션 (`BattleSession`)

- `inventory` 를 밖에서 받는다 (없으면 빈 가방)
- `item_targets(item)`: 지금 쓸 수 있는 대상들. 아군 차례가 아니면 비어 있음
- `use_item(index, target) -> bool`: `active` 가 있을 때만. 성공하면 가방에서 빼고 `changed`, 전투 종료 확인

### 드랍 (`StageRun`)

- 의뢰의 **일반 전투**에서 이겼을 때만 판정한다. 보스는 이기면 의뢰가 끝나므로 드랍 없음. F6 시험 전투도 없음
- 확률 `item_drop_chance` (기본 0.4) — 전투 화면 씬의 `@export` 로 둬서 에디터에서 바꾼다
- 성공하면 `items/consumables/` 의 모든 아이템 중 하나를 같은 확률로 고른다. 아이템이 하나도 없으면 드랍 없음
- 드랍 난수는 전투 난수(`Battle.rng`)와 따로

## 화면

```
[전투 화면 아래 오른쪽]
                                   [가방 2/5]  [차례 종료]

[TAB 또는 가방 버튼]
 ┌──────────── 가방 (2/5) ────────────┐
 │ [회복약]  [기력약]  [ ]  [ ]  [ ]  │
 └────────────────────────────────────┘
```

- 가방 패널(`Scenes/ui/battle_screen/bag_panel.tscn`)은 칸 5개가 씬에 고정으로 들어 있다 (칸 틀 `item_slot.tscn`)
- 열기/닫기: TAB(입력 액션 `toggle_bag`) 또는 가방 버튼. ESC·우클릭은 "끌고 있는 아이템 취소 → 가방 닫기" 순서
- **아이템도 카드처럼 드래그로 쓴다** (2026-11-17 사용자 결정). 가방 칸을 누른 채 끌면 그 칸 위쪽 가운데에서 마우스까지 카드와 같은 휜 화살표(`TargetArrow`)가 나오고, 쓸 수 있는 아군이 빛난다
  - 아군 위에서 떼면 사용 → 가방은 열린 채 남는다
  - 그 밖의 곳에서 떼면 (끌지 않고 그 자리에서 뗀 클릭도) 고르기가 취소되고 아이템은 가방에 남는다 — 카드의 2026-11-15 규칙과 같다
  - 화살표 색은 카드와 같다: 쓸 수 있는 아군 위면 유효, 아니면 무효
- 아이템을 고르면 고른 카드는 내려놓고, 카드를 고르면 고른 아이템을 내려놓는다
- 쓸 수 없는 때(적 차례, 연출 중, 전투 끝)는 아이템이 어둡고 눌러도 반응 없음. 가방 열어 보기는 언제든 가능
- 마우스를 올리면 이름·설명·효과 줄(`HP 회복 +30`, `SP 회복 +20%`)이 뜬다
- 전투 기록: `아이템: 회복약 → 홍연`. 회복 숫자는 지금의 회복 숫자 그대로

### 결과 창의 드랍

```
        승리
  아이템 획득: 회복약
  [받기]  [넘어가기]            ← 빈 칸이 있을 때

        승리

  [회복약] [기력약] [회복약] [기력약] [힘의 물약]   ← 바꿀 칸을 누름
  [넘어가기]
```

## 내 판단으로 정한 것 (틀리면 고칠 것)

- 폴더: 스크립트 `Scripts/items/`, 데이터 `items/consumables/`
- SP 회복은 대상 아무나에게 쓸 수 있다. SP 는 자기 차례 시작에 최대치로 맞춰지므로 사실상 **지금 차례인 캐릭터**에게 쓸 때만 의미가 있다
- 시험 아이템 수치 (회복약 HP +30, 기력약 SP +2)
- 드랍 확률은 전투 화면 씬의 `@export`
- 꽉 찬 가방에 드랍이 오면 바꾸기 / 넘어가기
- 아이템 사용은 연출 대기열에서 "즉시 단계"로 처리 (전용 연출 없음)
