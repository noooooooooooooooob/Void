# 사무소 화면과 공허 지도 설계

작성: 2026-11-08 · 브랜치 `feat/office-hub` · 상태: 구현 완료 (공허 7곳 — 검토 때 배경 7장 전부 쓰기로 함)

## 1. 목적

지금 게임은 시작 화면에서 곧바로 스테이지 지도로 들어간다. 기획의 핵심 루프("월드맵에서 의뢰 선택 → 스테이지 → 보상 → 파티/덱 편집 → 다음 의뢰")에 맞게,
시작 화면과 스테이지 사이에 **사무소(허브)** 와 **공허 지도**를 넣는다. 플레이테스트를 빠르게 하도록 시작 화면에 **개발용 바로가기**를 둔다.

## 2. 목표 / 비목표

목표
- 시작 → 사무소 → 공허 지도 → 공허 선택 → 스테이지(기존) → 끝나면 공허 지도로 복귀
- 사무소 메뉴 5개: 창고 · 사원 명부 · 카드 공방 · 의뢰/출발 · 하루 마치기 (설정집 확정 목록)
- 사원 명부에서 캐릭터 스탯과 캐릭터별 덱, 카드 공방에서 공용 카드를 볼 수 있다
- 공허 장소는 `.tres` 데이터로 만든다. 장소마다 이름·설명·지도 위 위치·전투 배경이 다르다
- 시작 화면 개발용 바로가기 (개발 빌드에서만 보임)

비목표 (이번에 안 함)
- 배경 그림 속 물건 위치에 버튼 배치 (설정집 확정 사항이지만 그림이 정해진 뒤에. 지금은 단순 메뉴)
- 하루 마치기 동작 (버튼만, "준비 중")
- 창고의 실제 아이템 (아이템 데이터가 아직 없음)
- 덱 편집 (보기만)
- 저장 / 불러오기 (진행 상태는 게임을 끄면 사라진다)
- 전투 화면 사선 원근 + 캐릭터 그림 (다음 단계, 설계 따로)

## 3. 화면 흐름

```
시작 화면 ──시작──▶ 사무소 ─┬─ 창고        ──뒤로──▶ 사무소
   │                        ├─ 사원 명부   ──뒤로──▶ 사무소
   │ (개발용 바로가기)        ├─ 카드 공방   ──뒤로──▶ 사무소
   └──▶ 각 화면으로 바로      ├─ 하루 마치기 (준비 중, 비활성)
                            └─ 의뢰/출발 ──▶ 공허 지도 ──공허 선택·들어가기──▶ 스테이지 지도(기존)
                                              ▲   └──뒤로──▶ 사무소
                                              │
               의뢰 성공(보스 승리) / 실패(패배) ┘
```

- 의뢰가 끝나면 시작 화면이 아니라 **공허 지도로 돌아간다** (CLAUDE.md: 보스 승리 = 성공, 패배/도주 = 실패 → 월드맵 복귀)
- 성공한 공허는 지도에 "정화됨" 표시 (게임을 끄면 사라짐, 저장은 비목표)

## 4. 화면별 내용

### 4.1 사무소 (`Scenes/ui/office/office.tscn`)
- 세로 버튼 메뉴 5개. 하루 마치기는 비활성 + "준비 중"
- 제목 "사무소". 배경은 단색(나중에 사무소 그림으로 바꾸고 버튼을 물건 위치로 옮긴다)

### 4.2 창고 (`Scenes/ui/storage/storage.tscn`)
- 지금은 "아직 아이템이 없다" 안내와 뒤로 버튼만. 아이템 데이터가 생기면 목록을 채운다

### 4.3 사원 명부 (`Scenes/ui/roster/roster.tscn`)
- 왼쪽: 캐릭터 목록 (지금은 홍연만)
- 오른쪽: 고른 캐릭터의 이름·스탯(HP, SP, 공격, 방어, 속도 범위, 이동, 행동 횟수)·패시브·장비, 그 아래 덱 카드(`card_view.tscn` 재사용, 덱 편집 화면이므로 % 표시)
- 캐릭터 목록은 데이터 파일 하나(`entities/roster.tres`, 플레이어 캐릭터 `UnitData` 배열)에서 읽는다. 폴더를 통째로 읽으면 시험용 적·시험용 홍연까지 섞이기 때문

### 4.4 카드 공방 (`Scenes/ui/card_workshop/card_workshop.tscn`)
- 공용 카드(덱 없음 = `cards/data/common/`)만 보여준다. 기존 카드 갤러리(`card_gallery.tscn`)를 "공용" 덱으로 고정해서 넣는다

### 4.5 공허 지도 (`Scenes/ui/void_map/void_map.tscn`)
- 배경: 세계 지도 그림 (`ProjectVoid_Assets/world/` 중 하나를 `Art/ui/` 로 가져옴)
- 공허 장소마다 표식(점 + 이름). 위치는 각 공허 데이터의 `map_position`
- 표식 클릭 → 오른쪽 정보 패널(이름, 설명, 층, 정화 여부) + "들어가기" 버튼. 키보드: 엔터
- 들어가기 → 그 공허로 새 의뢰 시작 → 스테이지 지도

## 5. 데이터

### 5.1 공허 장소 `VoidSiteData` (Resource, `Scripts/stage/void_site_data.gd`)
| 칸 | 타입 | 뜻 |
|---|---|---|
| `id` | String | 고유 이름 (정화 기록용) |
| `display_name` | String | 화면 이름 (예: "산중 신사") |
| `description` | String (여러 줄) | 정보 패널 설명 |
| `map_position` | Vector2 | 공허 지도 그림 위 위치 (px, 지도 왼쪽 위 기준) |
| `floor` | int = 1 | 층. 지금은 1층 규칙뿐 |
| `background` | PackedScene | 이 공허의 전투 배경 씬 (`Scenes/backgrounds/`) |

- 파일: `voids/<id>.tres`. 처음엔 2곳 — 산중 신사(`mountain_shrine`), 흑수정 동굴(`crystal_flame_cave`). 프로젝트 `Art/Terrian/` 에 있는 배경 2장을 쓴다
- 더 넣고 싶으면 `ProjectVoid_Assets/backgrounds/` 의 나머지 5장(거울 대성당, 사이버펑크 거리 등)을 가져와 배경 씬 + `.tres` 를 추가한다

### 5.2 사원 명부 `RosterData` (Resource, `Scripts/battle/roster_data.gd`)
- `units: Array[UnitData]` — 플레이어가 고용한 캐릭터. 파일 `entities/roster.tres` (지금은 홍연 하나)

### 5.3 의뢰 진행 `StageRun` 변경
- `start_run(site: VoidSiteData, seed := 0)` — 어느 공허인지 기억
- 전투 화면은 배경을 `StageRun.battle_background()` 에서 받는다 (공허의 배경, 없으면 전투 데이터 배경)
- 의뢰 끝: 성공이면 그 공허 id 를 `cleared_sites` 에 넣고 공허 지도로, 실패면 바로 공허 지도로
- 파티는 사원 명부 캐릭터로 만든다 (지금은 전투 데이터의 아군 배치 위치에 명부 첫 캐릭터. 파티 선택은 노션 규칙 확인 후)

## 6. 화면 전환 `Router` (자동 로드, `Scripts/ui/router.gd`)
- 화면 이름 → 씬 경로 표를 한곳에 둔다: `TITLE, OFFICE, STORAGE, ROSTER, CARD_WORKSHOP, VOID_MAP, STAGE_MAP, BATTLE, ROOM`
- `Router.goto(Router.Screen.OFFICE)` 로 이동. `StageRun._go` 도 이걸 쓰게 바꾼다
- 씬 파일을 옮기면 이 표만 고치면 된다

## 7. 개발용 바로가기 (시작 화면)
- 시작 화면 오른쪽 아래 작은 패널 "개발용". `OS.is_debug_build()` 일 때만 보임 (출시용 빌드에는 안 나옴)
- 버튼: 사무소 · 창고 · 사원 명부 · 카드 공방 · 공허 지도 · 스테이지(새 의뢰, 첫 공허) · 전투(시험 전투 바로)

## 8. 정리 작업 (같이 함)
- `Art/Terrian/` → `Art/backgrounds/`, 파일 이름 영어로 (`mountain_shrine_terrace.png`, `crystal_flame_cave.png`). 에디터를 끈 상태에서 Godot 헤드리스로 옮겨 참조 유지
- 흑수정 동굴 배경 씬 `Scenes/backgrounds/crystal_flame_cave.tscn` 추가 (산중 신사 씬과 같은 구조)

## 9. 테스트 (GUT)
- `VoidSiteData` / `RosterData` 데이터 파일이 열리고 칸이 채워져 있다 (`voids/*.tres` 전부, 배경 씬 있음)
- `Router` 의 모든 화면 경로에 실제 씬 파일이 있다
- `StageRun`: 공허로 시작 → `site` 기억, 파티 = 명부 캐릭터, 배경 = 공허 배경 / 성공 → `cleared_sites` 에 추가 / 실패 → 추가 안 됨
- 화면: 사원 명부가 명부 캐릭터 수만큼 목록을 만들고, 고르면 덱 카드 수만큼 카드를 그린다 / 공허 지도가 공허 수만큼 표식을 만들고, 고르면 정보 패널이 그 공허를 보여준다 / 개발용 패널은 디버그 빌드에서 보인다
- 기존 테스트 270개 유지
