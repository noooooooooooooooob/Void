# 연출 타임라인 설계 (유니티 Timeline 식으로 에디터에서 보며 짜기)

2026-11-19. 상태: 구현됨 (대상 타임라인 이동은 이번 범위 밖). 구현 중 바뀐 이름: 자리 맞추기 클래스 `PerformanceSpace`(`StageMap` 은 의뢰 지도와 겹침), 월드 묶음은 `World`+`WorldFront` 둘(그리기 순서 유지). 이전 설계 `2026-11-14-card-performance-design.md` 의 5·6장을 대체한다.

## 왜

연출을 고칠 때마다 전투를 돌려 카드를 써 봐야 결과가 보인다 (사용자: "전투 매번 돌리는 게 번거로워").
지금 연출 씬은 에디터에서 ▶ 해도 아무것도 안 보인다:
- `perform` 의 트랙이 전부 Call Method 트랙이고, Godot 에디터 미리보기는 Call Method 키를 실행하지 않는다
  (동작 전환 `Actor.play("punch")` 도 메서드 키라 그림이 안 바뀜).
- 이동은 `move(x, y, 시간)` 키로 전투 화면에 맡겨서 위치가 타임라인에 없다 → 곡선 편집도 미리보기도 불가.
- 이 씬만 F6 해도 `play()` 를 부르는 사람이 없어 멈춰 있다.

## 사용자가 정한 것

- **유니티 Timeline 처럼**: 한 타임라인에서 캐릭터 동작 조절, 여기서 저기로 이동, 카메라 이동·줌, 이 시점에 이펙트, 효과음 등을 짜고, 위치를 바꾸면 자연스럽게 이어지고, 움직임은 **그래프(곡선)** 로 조정.
- **카메라 무빙**이 되어야 한다.
- **Godot 안에서** 볼 수 있게 (웹 편집기는 나중 얘기, 이번 범위 아님).
- 이전 설계에서 유지: 위치 기준은 **대상이 서 있는 칸**, 적이라고 좌우 반전하지 않음, 피해는 나누지 않고 `hit` 는 여러 번, 결과는 `show_results` 키로.

## 목표

1. 연출 씬을 열고 AnimationPlayer ▶ 를 누르면 **캐릭터 동작·이동 경로·카메라 범위·이펙트·효과음**이 에디터에서 그대로 보이고 들린다.
2. 이동·카메라는 Godot 의 **Bezier 커브 트랙**으로 곡선 편집할 수 있다.
3. 실제 전투에서 대상·행위자 칸이 어디든, 에디터에서 짠 모양이 **자연스럽게 늘어나/줄어들어** 맞는다 (아래 2장).
4. 카메라 트랙대로 전투 화면의 **월드(배경·격자·유닛·연출)** 만 움직이고 UI(손패·버튼·라벨)는 고정. 연출 끝나면 부드럽게 원위치.
5. **연출 미리보기 씬**: F6 한 번으로 실제 전투 화면에서 고른 연출을 반복 재생 — 피격 반응·숫자·히트스톱까지 진짜와 똑같이.
6. 연출 씬이 없는 카드, 기존 전투 규칙·테스트는 그대로.

## 하지 않는 것

- 웹 타임라인 편집기, 유니티식 클립 블록 편집 패널(플러그인) — Godot AnimationPlayer 를 그대로 쓴다
- 에디터 ▶ 에서 `hit`·`show_results` 반응(흔들림·숫자·히트스톱) 보기 — 이건 미리보기 씬(목표 5)에서
- 대상(맞는 쪽)을 타임라인으로 움직이기 — `hit` 자동 반응(흔들림·넉백) 유지 *(제 판단, 아래 "사용자 확인")*
- 연출 건너뛰기·배속(게임 내), 배경음, HP 바 잔상
- 브람 돌주먹 외 연출 제작

## 접근 방법 (검토한 것)

| 안 | 내용 | 판단 |
|---|---|---|
| **A. AnimationPlayer + 연출 씬 구조 변경 + 미리보기 씬** | Godot 기본 타임라인(곡선·파형·어니언 스킨)을 그대로 쓰고, 막히던 원인인 씬 구조만 고침 | **선택** (사용자: "일단 고도에서 볼 수 있게") |
| B. 유니티식 Timeline 플러그인 직접 제작 | 클립 블록 패널 | 작업량 몇 배, Godot 기능 재구현 |
| C/D. 웹 미리보기 / 웹 편집기 → 가져오기 | 카드 에디터 같은 흐름 | 화면이 Godot 과 어긋남, 작업량 최대. 나중 후보 |

## 구조

### 1. 연출 씬 규약 (새)

`Scenes/performances/<카드 이름>.tscn`, 루트 `CardPerformance`(Node2D). **씬은 게임 화면 크기로 짠다** (2026-11-19 사용자 결정 — 카메라 사각형이 실제 화면과 같게): 좌표 1 = 화면 1px, Actor·Target 미리보기 그림에 유닛 박스 그림 배율(0.2)을 직접 넣는다. 실행 때 루트 배율 = 행위자 그림 global_scale ÷ Actor 배율.

| 노드 | 종류 | 역할 | 실행할 때 |
|---|---|---|---|
| `Home` | Marker2D | 행위자가 원래 서 있는 자리 (에디터 기준점) | 안 보임 |
| `Target` | Marker2D + 자식 미리보기 그림 | 기준 대상이 서 있는 자리. 미리보기용 적 그림을 자식으로 | 자식 그림 숨김 |
| `Actor` | AnimatedSprite2D | 연출하는 캐릭터. 시작 위치는 `Home` 위 | 행위자의 `battle_frames` 로 바뀜 |
| `Camera` | Node2D(카메라 표시용) | 위치·`zoom`·회전을 트랙으로 키. 에디터에서 화면 범위 사각형이 보이게 | 값만 읽어 전투 화면 월드에 적용, 안 보임 |
| 이펙트들 | AnimatedSprite2D / GPUParticles2D 등 자유 | 평소 숨김, 트랙으로 켜고 재생 | 그대로 |
| 효과음 | AudioStreamPlayer(2D) | **Audio Playback 트랙**으로 시점 지정 | 그대로 |
| `AnimationPlayer` | | 애니메이션 `perform` 하나 | 그대로 |

트랙 규칙:
- **동작 그림 전환은 속성 트랙** (`Actor:animation`, 필요하면 `Actor:frame`). 에디터 ▶ 에서 바뀌어 보여야 한다.
- **위치·카메라는 Bezier 트랙 권장** (`Actor:position:x/y`, `Camera:position:x/y`, `Camera:zoom` 등). 일반 값 트랙도 허용.
- 이펙트 켜기·재생: 속성 트랙(`visible`, `frame`, `emitting`) 또는 Animation Playback 트랙.
- 전투 화면이 반응해야 하는 것만 **Call Method 키** (경로 `.`): `hit()`, `show_results()`, `zoom(세기, 시간)`(기존 줌 펀치 유지). **`move()` 는 없앤다** — 이동은 위치 트랙으로.
- 기존 루트 `@export`(return_time, hit_effect, hit_sound, hit_shake, hitstop_time, knockback) 유지.

### 2. 자리 맞추기 (에디터 → 실제 칸)

에디터에서는 `Home` 과 `Target` 사이 거리가 고정이지만 실제 전투에서는 칸마다 다르다. 연출 씬 안 **위치를 가진 노드들(Actor, Camera, 이펙트)** 의 매 프레임 위치 p 를 다음으로 바꿔 화면에 놓는다 *(제 판단 — 사용자가 따로 신경 쓸 것 없게 자동)*:

```
d  = Target - Home                       (에디터)
w  = clamp( (p - Home)·d / |d|², 0, 1 )  ← Home→Target 직선 위에서 얼마나 갔나
p' = p + (1-w)·(실제Home - Home) + w·(실제Target - Target)
```

- `Home` 위에 있으면 실제 행위자 칸, `Target` 위에 있으면 실제 대상 칸, 그 사이는 비율대로 늘어남. 직선에서 위아래로 벗어난 거리(점프 높이 등)는 그대로.
- `Target` 너머(뒤로 돌아가기)는 대상 기준, `Home` 뒤(뒷걸음)는 행위자 기준.
- 대상이 없는 카드(자신)는 `실제Target = 실제Home + d` (에디터 모양 그대로).
- 범위 공격은 기준 대상(지정한 유닛, 근접이면 맨 앞 적)의 칸.
- "실제 칸" 은 이전 설계대로 **화면에 지금 보이는** 박스 위치.
- 구현 제약: AnimationPlayer 가 쓴 값을 덮어쓰면 다음 프레임에 다시 써지므로, **애니메이션이 쓴 원래 값과 화면 위치를 분리**해야 한다(예: 매 프레임 애니메이션 처리 뒤 원래 값을 읽어 보이는 대리 노드에 놓기). 방법은 빌더 몫.
- 에디터에서는 바꿀 것이 없으므로 짠 그대로 보인다.

### 3. 카메라

- 전투 화면에 **월드 묶음**(배경, 아군·적 격자/유닛, PerformanceLayer, FloatLayer)과 **UI**(라운드·차례 표시, 손패, 하단 버튼, 로그, 가방, 결과 창, 화살표)를 나눈다. 지금은 모두 루트의 형제라 **battle_screen.tscn 구조 변경**이 필요 — 스크립트의 노드 경로·`tests/ui/` 영향 범위를 먼저 파악할 것 (CLAUDE.md "씬 구조 변경 시").
- 연출 중 매 프레임 `Camera` 의 (2장으로 바꾼) 위치·zoom·회전을 월드 묶음에 적용: 카메라 위치가 화면 중심에 오도록 이동 + 확대 + 회전.
- 연출 씬에 Camera 키가 하나도 없으면 카메라는 움직이지 않는다 (기존 연출과 같음).
- 카메라 기본 자리 = 연출 시작 시 화면 그대로. 에디터에서 Camera 기본 위치는 `Home`·`Target` 중간, zoom 1 *(제 판단)*.
- 연출이 끝나면 `return_time` 동안 원래 화면으로 부드럽게 복귀 (행위자 복귀와 같이).
- 기존 `zoom()` 줌 펀치와 화면 흔들림은 카메라 위에 더해진다.
- 에디터에서 카메라 범위를 보이게 하는 방법(Camera2D 노드를 쓰되 current 끄기, 또는 `@tool` 로 사각형 그리기)은 빌더 몫. 범위 크기 = 게임 화면 크기 / zoom.

### 4. 재생 순서 (카드 단계 하나, 이전 설계 6장 대체)

1. 연출 씬이 없으면 지금과 같음.
2. 연출 씬을 연출 레이어에 띄우고, `Home`→행위자 그림 자리, `Target`→기준 대상 박스 자리로 2장 맞추기를 준비. `Target` 미리보기 그림 숨김. 행위자 박스 그림 숨김.
3. `perform` 재생. 매 프레임 2장 적용, 카메라 적용. 메서드 키에 따라 피격 반응·결과·줌 펀치.
4. 끝나면 결과를 아직 안 보였으면 보이고, Actor 가 `Home` 이 아닌 곳에 있으면 `return_time` 동안 행위자 칸으로, 카메라도 원위치.
5. 연출 씬을 지우고 행위자 그림을 다시 보인다.

히트스톱(`set_paused`)은 AnimationPlayer·AnimatedSprite2D 와 함께 파티클·효과음도 멈추는지는 빌더가 정함 (최소: 지금과 같음).

### 5. 연출 미리보기 씬

- `Scenes/performances/performance_preview.tscn` (스크립트 `Scripts/performances/performance_preview.gd`). 에디터에서 열고 F6.
- 실제 `BattleScreen` 을 시험 전투(`battles/test_battle.tres`)로 띄우고, 위에 작은 개발용 패널:
  - **연출이 있는 카드 목록**(`cards/data/` 중 `performance` 가 있는 카드) 선택
  - 행위자(그 카드를 가진 유닛, 없으면 첫 아군)·기준 대상(적 목록) 선택
  - ▶ 재생 / 반복 켜기 / 속도(0.25·0.5·1×)
- ▶ 할 때마다 전투 상태를 처음으로 되돌린 뒤 그 카드를 실제로 쓰게 해서(SP·조건 무시) 숫자·피격 반응까지 진짜와 똑같이.
- 씬 인스펙터 `@export` 로 기본 카드를 정해 두면 F6 즉시 재생 *(제 판단 — 한 카드를 계속 다듬을 때 클릭 줄이기)*.
- 파일을 고친 뒤 다시 보려면 F6 을 다시 (실행 중 자동 새로고침은 하지 않음).

### 6. 브람 돌주먹 옮기기

`bram_stone_fist.tscn` 을 새 규약으로 다시 만든다: `move` 키 → Actor 위치 Bezier 트랙, `Actor.play` 키 → `Actor:animation` 속성 트랙, `hit`·`show_results` 유지. 카메라 예시로 맞는 순간 대상 쪽으로 살짝 줌인 키 몇 개 *(제 판단 — 카메라가 되는지 보여 주는 견본)*.

## 제약

- 씬·리소스는 에디터(또는 에디터를 끈 상태에서 Godot 이 저장)로 만든다. 손으로 `.tscn` 작성 금지. GoPeak `scene-node-set` 은 인스턴스 있는 씬에 쓰지 않는다.
- 테스트는 프로젝트 복사본에서 GUT.
- 순수 계산(2장 자리 맞추기, 카메라 변환)은 `RefCounted` 로 빼서 GUT 테스트.

## 사용자 확인

- 대상(맞는 쪽)도 타임라인으로 움직이게(띄우기·날려 보내기 등) 할지 — 지금 설계는 하지 않음.

## 빌더 몫

- 2장 원래 값/보이는 위치 분리 방법, 카메라 범위 표시 방법, 미리보기 패널 배치, 월드 묶음 노드 이름.
