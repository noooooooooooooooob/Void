# 연출 화면 창 (에디터에서 프레임을 옮기며 실제 게임 화면 보기) 설계

2026-11-19. 상태: 구현됨 (유닛 틀 = 편 색 박스 + 그림, 화면은 size_2d_override 로 1920×1080 전체를 줄여 그림). 앞 설계: `2026-11-19-performance-timeline-design.md`

## 왜

사용자: "지금 프레임을 내가 직접 옮기면서 실제 게임 화면의 상황처럼 보고 싶다." (유니티 Timeline 스크럽 + Game 뷰)
지금 에디터 연출 씬은 배경·격자가 없고 카메라는 사각형뿐이며, F6 미리보기는 재생만 되고 프레임 이동이 안 되며 고칠 때마다 다시 실행해야 한다.

## 사용자가 정한 것

- **A안**: 에디터 안에 "게임 화면" 창. 애니메이션 패널의 타임라인 막대를 끌면 그 프레임의 실제 전투 화면(배경·격자판·유닛·실제 칸 거리로 늘린 위치·카메라 구도)이 창에 바로 그려진다. 키를 고치면 즉시 반영.
- 피격 반응(흔들림·숫자·히트스톱)·UI 는 이 창에 없음 → F6 미리보기로 확인.

## 목표

1. 연출 씬(루트 `CardPerformance`)을 에디터에서 열면 하단 패널에 **"연출 화면"** 탭이 생긴다. 다른 씬이면 탭에 안내만.
2. 창 안: 16:9 게임 화면(1920×1080 을 창에 맞춰 축소). 시험 전투(`battles/test_battle.tres`)의 배경 씬과 격자판, 아군 그림과 **적 하나**(시험 전투의 첫 적 = 대상, 사용자 결정)가 실제 칸 자리에.
3. 연출 씬의 **지금 상태**(타임라인 막대를 끌거나 ▶ 할 때 AnimationPlayer 가 노드에 넣는 값)를 매 에디터 프레임 따라 그린다:
   - Actor·이펙트 등 위치는 실제 게임과 같은 규칙으로 배치·늘림 (Home → 행위자 그림, Target → 대상 그림, `PerformanceSpace`)
   - 행위자 원래 그림은 숨김, Target 미리보기 그림은 숨김 (실제 게임과 같게)
   - 카메라: `perform` 0초의 카메라 자세 대비 지금 자세만큼 월드(배경·격자·유닛·연출)를 움직임 (`CameraMath`, 실제 게임과 같은 식)
4. 창 위 작은 줄: **행위자**(아군) 고르기. 기본 = 이 연출을 쓰는 카드를 덱에 가진 아군. 대상은 그 적 하나로 고정.
5. 실제 게임 코드와 같은 계산을 쓴다 (따로 흉내 내지 않음): 자리 맞추기·카메라 식은 공용 함수로.

## 하지 않는 것

- 피격 반응·결과 숫자·UI·효과음 (F6 미리보기)
- 창에서 직접 키 편집·드래그 (편집은 지금처럼 2D 화면·애니메이션 패널)
- 시험 전투 말고 다른 전투 데이터 고르기 *(제 판단 — 필요하면 나중에 칸 하나 추가)*
- 파티클 재생 상태 같은 세세한 이펙트 상태 따라 하기: 위치·회전·크기·보이기·색·AnimatedSprite2D 동작/프레임·Sprite2D 프레임만 따라 함 *(제 판단)*

## 접근 방법

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 에디터 플러그인 하단 패널 + SubViewport 에 무대를 깔고 편집 중인 연출 씬을 복제해 매 프레임 상태를 옮겨 그림** | 실제 전투 화면 씬(`BattleScreen`)은 에디터에서 돌지 않는 스크립트라 쓰지 않고, 배경 씬·격자판(이미 `@tool`)·유닛 그림만 깐다 | **선택** |
| B. F6 미리보기에 시간 막대 | 진짜 화면이지만 고칠 때마다 재실행, 지나간 hit 되돌리기 어색 | 사용자가 A 선택 |

## 구조

### 1. 플러그인
`addons/performance_stage_view/` (`plugin.cfg`, `plugin.gd`, 창 씬 `stage_view.tscn` + 스크립트 `stage_view.gd`) *(플러그인 소유 씬이라 addons 안에 둠 — CLAUDE.md 의 플러그인 예외)*. 프로젝트 설정에서 켠다.
- `plugin.gd`: 하단 패널에 `stage_view.tscn` 을 붙인다. 편집 중인 씬이 바뀌면(`scene_changed`) 창에 루트를 넘긴다. 매 에디터 프레임 창을 갱신한다.

### 2. 창 (`StageView`, `@tool` Control)
- 씬 구성(에디터 자산으로): 위 줄(`%ActorList` OptionButton, 안내 Label `%Hint`) + `SubViewportContainer`(stretch) → `SubViewport`(1920×1080) → `%World`(Control) → `%Background`(배경 씬이 들어갈 자리)·`%Units`(유닛 그림 자리, 안에 숨긴 틀 `%UnitTemplate` = AnimatedSprite2D, 배율·offset 은 `unit_token.tscn` 의 Sprite 와 같게)·`%PerfLayer`(연출 복제가 들어갈 자리).
- `set_battle(data: BattleData)`: 배경 씬을 넣고, 격자판 두 개를 찾아 `use_cells(cols, rows)` 로 칸을 켜고, 아군 전원과 첫 적 하나에 대해 유닛마다 틀을 복제해 칸 중심(`GridCell.center()` 의 화면 좌표 — 실제 유닛 박스 그림 자리와 같음)에 놓는다. 그림 묶음이 없는 유닛은 틀의 기본 네모 *(빌더 몫)*.
- `set_source(perf: Node)`: 편집 중인 연출 루트를 받는다. 복제본(`duplicate()`)을 `%PerfLayer` 에 넣고 AnimationPlayer 는 지운다. 노드 구성이 바뀌면(자식 수·이름) 다시 복제.
- `sync()`: 매 프레임
  1. 원본 → 복제본으로 노드 경로가 같은 것끼리 상태를 옮긴다 (위 "하지 않는 것" 의 목록)
  2. 실제 게임과 같은 배치: 루트 배율 = 행위자 그림 배율 ÷ Actor 배율, Home 이 행위자 그림 자리에, 대상이 자신이 아니면 Target → 대상 그림 자리로 `PerformanceSpace.map_point`
  3. 행위자 유닛 그림 숨김, Target 자식 숨김
  4. 카메라: `perform` 0초의 카메라 자세(애니메이션 값을 0초로 계산, 없으면 노드 값)와 지금 자세를 같은 방식으로 늘려 `CameraMath.view` → `%World` 에 적용 (실제 게임의 `t * view * t⁻¹` 와 같은 식)
- 계산 재사용: 실제 게임(`CardPerformance`·`PerformanceQueue`·`BattleScreen`)의 배치·카메라 식을 **공용 정적 함수**로 빼서 양쪽이 같이 쓴다. `PerformanceSpace`·`CameraMath` 는 에디터에서도 부를 수 있게 `@tool`.

### 3. 행위자·대상 고르기
- 행위자 기본: 연출 씬 경로를 `performance` 로 가진 카드(`cards/data/`, 강화본 포함)를 덱에 가진 아군. 없으면 첫 아군.
- 대상: 시험 전투의 첫 적 하나만 깔고 그 적이 대상. 행위자 목록을 바꾸면 바로 반영.

## 제약

- 플러그인 스크립트는 `addons/` 에. 한국어 주석 규칙 동일.
- 창 씬(.tscn)은 에디터를 끈 상태에서 헤드리스로 만든다 (`--editor` + uid 유지). **에디터가 켜져 있으면 쓰기 직전에 멈추고 사용자에게 끄기를 요청.**
- 플러그인은 에디터 성능에 영향 없게: 연출 씬이 아닐 때는 아무것도 안 함.
- 공용 계산은 GUT 로 테스트. 창은 헤드리스 GUT 에서 `set_battle`/`set_source`/`sync` 를 직접 불러 테스트 (에디터 없이).
