# 카드·효과·턴 시스템 설계

- 날짜: 2026-11-03
- 대상: Project Void (Godot 4.7.2, GDScript)
- 상태: 초안 (승인 대기)

## 1. 목적

카드, 버프·디버프, 패시브, 장비가 **같은 효과 부품**을 조합해서 동작하게 만든다. 흔한 효과는 한 번만 구현하고, 카드와 상태는 `.tres` 데이터로 조합한다. 부품으로 안 되는 1장짜리 효과만 전용 스크립트를 쓴다.

**이 방식을 고른 이유**
- 카드마다 스크립트를 붙이면 같은 코드가 반복되고, 공식을 하나 바꿀 때 전부 고쳐야 한다.
- 적도 같은 카드 규칙을 쓴다 (노션 확정).
- 노션 버프 목록(출혈, 혈갑, 핏방울, 피의 갈망 등)이 모두 "특정 시점에 → 효과" 또는 "수치 보정" 형태라서, 카드 효과와 같은 부품으로 표현할 수 있다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 카드 사용: 조건 확인 → 비용 지불 → 효과 실행
- 비용: SP, 상태 수치(고정량 소모, 전부 소모)
- 효과가 "이번 사용에서 소모한 양" 같은 값에 비례할 수 있음
- 상태(버프·디버프·패시브)와 장비가 페이즈·전투 이벤트에 구독해서 반응
- 스탯 보정: % 먼저, 고정값 나중
- 속도 순 개별 행동 턴: 속도는 범위, 라운드마다 행동(행동 횟수만큼)마다 굴림, 속도가 바뀌면 즉시 재정렬
- 캐릭터별 덱·손패·버린 카드 더미·SP
- 적: 일반 적은 자기 덱에서 한 장씩, 보스는 정해진 순서대로
- 카드 대체(패시브가 특정 카드를 다른 카드로 바꿈)
- 전용 스크립트 효과(예외 처리용)

**비목표 (이번에 안 함)**
- 웹 카드 에디터 변경, 에디터 JSON → `.tres` 변환기
- 격자 이동 UI, 대상 지정 UI, 카드 연출
- 궁극기 게이지, 협공·친밀도, 어그로 규칙, 장비 숙련도·등급
- 스태미너가 0일 때 들어가는 기절·탈진 상태의 실제 효과 (미정)
- 의뢰 스테이지, 월드맵, 보상

**반목표 (이렇게 되면 실패)**
- 새 카드를 추가할 때마다 코드를 짜야 하는 구조
- 같은 시점의 효과 실행 순서가 실행할 때마다 달라지는 것
- 상태가 사라진 뒤에도 구독이 남아서 계속 반응하는 것
- 반응이 반응을 부르며 무한 반복되는 것

## 3. 확정된 게임 규칙

노션 "구현 확정"(2026-10-11)과 이번 대화에서 정한 것이다.

### 3.1 턴
- **속도는 최소~최대 범위**이고, **행동 횟수**만큼 매 라운드 시작 시 행동마다 따로 굴린다 (2026-11-04 사용자 결정).
  - 예) 행동 횟수 2, 속도 3~9 → 이번 라운드 [8, 4] 를 굴리면 속도 8 로 한 번, 속도 4 로 한 번 행동
  - 감속·가속 보정은 **굴린 값에 적용**한다.
- 라운드 시작 시 모든 유닛의 모든 행동을 **속도** 내림차순으로 줄 세운다. 행동 하나 = **온전한 차례 하나** (아래 차례 순서 전체를 거친다).
- 맨 앞부터 한 유닛씩 자기 차례를 진행한다. 전원이 한 번씩 행동하면 라운드가 끝난다.
- **속도가 바뀌면 즉시 반영한다.** 이번 라운드에 아직 쓰지 않은 행동들을 바뀐 속도로 다시 정렬한다. 이미 쓴 행동은 다시 들어오지 않는다. 같은 유닛의 남은 행동은 그대로 남는다 (행동 횟수가 2 면 첫 행동 뒤에도 한 번 더 행동).
- 한 유닛의 차례 순서:
  1. 차례 시작
  2. SP를 최대치로 회복
  3. 드로우 페이즈: 카드 드로우 (덱이 비면 버린 더미를 섞어 채움. 행동 중 드로우는 덱이 비면 못 뽑음 — 2026-11-04 사용자 결정)
  4. 대기 페이즈
  5. 행동: 카드 사용(여러 장 가능), 이동
  6. 엔드 페이즈: 손패를 **전부 버림**
  7. 차례 종료
- 행동 순서 표시가 실시간으로 바뀔 수 있도록, 순서가 바뀔 때마다 알린다.

### 3.1.1 전투 격자
- 아군 격자와 적 격자가 **따로** 있다. **왼쪽이 아군, 오른쪽이 적**이고 서로 마주 본다 (노션 카드 페이지 그림, 사용자 확인).
- 칸 좌표는 각 편 격자 안의 `Vector2i(열, 행)`이다. 열은 **가운데(상대 쪽)에 가까울수록 "앞"**이다. 아군은 오른쪽 끝 열, 적은 왼쪽 끝 열이 맨 앞이다.
- 근접: 사용자와 **같은 행**에서, 적 격자의 맨 앞 열부터 찾아 처음 만나는 적에게 적용한다.
- 광역 오프셋은 **기준 유닛이 있는 편의 격자 안에서만** 적용하고, 격자 밖이나 빈 칸은 무시한다 — *설계자 판단*
- 오프셋의 x 방향은 "앞쪽이 +"로 통일해서, 아군과 적이 같은 카드를 써도 같은 모양으로 보이게 한다 — *설계자 판단*
- 한 칸에는 유닛 하나만 들어간다 — *설계자 판단*
- **격자 크기는 전투마다 데이터로 정한다** (2026-11-04 사용자 결정). 행 수는 양쪽 편이 같고(근접 = 같은 행), 열 수는 편마다 다를 수 있다. 기본값은 3행 × 4열. 전투 데이터(적 구성 + 격자 크기) 리소스는 나중에 만든다.

### 3.2 덱
- 캐릭터마다 덱, 손패, 버린 카드 더미가 따로 있다.
- SP는 캐릭터별이며, 자기 차례가 시작될 때 가득 회복된다.

### 3.3 카드
- 공격 종류
  - 근접: 같은 행의 맨 앞 적에게 자동 적용. 그 행에 적이 없으면 사용 불가
  - 원거리: 상대 편 아무 유닛을 기준으로 지정
  - 아군: 아군 아무나(자신 포함)
  - 자신: 대상 지정 없이 즉시 사용
  - 빈 칸은 기준으로 지정할 수 없음
- 광역: 기준 유닛으로부터의 `Vector2i` 오프셋 배열
- 분류: 공격(빨강), 스킬(파랑), 특수(보라), 적 전용(검정)
- 효과 수치 = 스탯 × % (내림, 최소 1)
  - 피해·회복은 공격 스탯, 방어도는 방어 스탯 기준
- 방어 스탯은 받는 피해를 줄이지 않는다 (방어도 계수로만 쓴다).
- 치명타는 피해 효과에만 적용하고, 맞는 유닛마다 따로 판정한다.
- 계산 순서 — *설계자 판단*
  - `스탯 × % × 배율 × (치명이면 치명피해/100)` 을 전부 곱한 **마지막에** 내림하고, 최소 1로 맞춘다.
  - 치명피해 스탯은 배수다. 150이면 ×1.5.
  - 배율이 0이면(예: 소모한 수치 0) 최소 1을 적용하지 않고 0으로 둔다.

### 3.4 스탯
- HP, SP, 공격, 방어, 속도(최소~최대), 이동속도, 치명확률, 치명피해, 어그로, 스태미너, 행동 횟수
  - **속도**는 행동 순서(범위, 라운드마다 굴림), **이동속도**는 한 차례에 움직일 수 있는 칸 수다. 서로 다른 스탯이다.
  - **행동 횟수**는 한 라운드에 행동하는 횟수. 버프·장비로 바뀔 수 있다.
- 최종값 = `기본값 × (1 + %보정 합계) + 고정보정 합계`
  - % 보정 여러 개는 **더한다** (곱하지 않음) — *설계자 판단*
  - 장비 공격 보너스는 고정 보정이다.
- 상태가 바뀌어 속도 보정이 달라지면, 턴 순서 재정렬을 요청한다.

### 3.5 방어도 (쉴드)
- 방어도와 쉴드는 같은 것이다. 코드에서는 `block` 하나로 부른다.
- 피해를 받으면 **방어도를 먼저 깎고**, 남은 피해만 HP를 깎는다.
- **새 라운드가 시작될 때 모든 유닛의 방어도를 0으로 초기화**한다.
  - 예외("방어도 유지" 같은 상태)를 위해, 초기화 직전에 상태가 끼어들 수 있게 한다. 상태의 `modifiers`에 "방어도 유지" 플래그를 두거나, `ROUND_START` 이전 단계 이벤트에서 초기화를 막을 수 있게 한다. 구체적인 예외 규칙은 기획이 정해지면 데이터로 채운다.

### 3.6 스태미너
- 노션 아이디어 박스의 "흐트러짐"을 이렇게 부르기로 했다.
- **받은 피해만큼 깎인다. 방어도에 막힌 양도 포함한다.** 예: 피해 30, 방어도 20 → 방어도 −20, HP −10, 스태미너 −30
- **자신이 가한 피해의 절반만큼 회복한다** (사용자 결정). 내림, 최대치를 넘지 않는다.
  - "가한 피해"는 상대 스태미너를 깎은 양과 같은 값(방어도에 막힌 양 포함)을 쓴다 — *설계자 판단*. 예: 피해 30을 가함 → 내 스태미너 +15
  - **상태로 생긴 피해(출혈 등)는 아무도 "준" 것이 아니다** (2026-11-04 사용자 결정): 건 유닛을 기억은 하지만 피해를 준 것으로 치지 않는다 → 출혈 피해로는 아무도 스태미너를 회복하지 않고, 치명도 없다.
- 0이 되면 상태 하나(기절·탈진 등, 효과는 미정)를 부여한다.
- 전투가 끝나면 리셋한다.

### 3.7 이동
- 자기 차례의 행동 단계에서 **이동속도 스탯만큼 칸**을 움직일 수 있다.
- 자기 편 격자 안에서만 움직인다.
- 상하좌우 한 칸이 1이다. 대각선 이동은 없고, 다른 유닛이 있는 칸은 들어가거나 지나갈 수 없다 — *설계자 판단*
- 카드 사용 전후 아무 때나 나눠서 이동할 수 있다. 남은 이동력은 차례가 끝나면 사라진다 — *설계자 판단*
- 이동하면 근접 카드의 사용 가능 여부가 바뀔 수 있으므로, 이동 후 손패의 `can_play`를 다시 계산한다.
- 이벤트 `UNIT_MOVED`를 발행한다.

### 3.8 같은 시점 효과의 순서
- **구독한 순서**대로 실행한다. 별도 우선순위 값은 두지 않는다.

## 4. 구조

```
데이터 (Resource, .tres)              런타임 (전투 중)
─────────────────────────            ─────────────────────────
CardData                              BattleManager
 ├ costs:      Array[CardCost]          ├ TurnOrder (속도 순, 재정렬)
 ├ conditions: Array[CardCondition]     ├ BattleEvents (구독·발행)
 ├ effects:    Array[CardEffect]        └ units: Array[BattleUnit]
 └ (기존 필드: 이름, SP, 분류,                  ├ stats (StatBlock)
    공격 종류, 광역 등)                         ├ statuses: Array[StatusInstance]
                                               ├ deck / hand / discard
StatusData (버프·디버프·패시브)                 └ sp, block, stamina
 ├ triggers:     Array[StatusTrigger]
 ├ modifiers:    Array[StatModifier]   CardPlay (카드 1회 사용의 컨텍스트)
 └ replacements: { CardData: CardData }  ├ user, card, targets
                                         └ values: { "consumed:출혈": 5, ... }
EquipmentData
 └ statuses: Array[StatusData]  (장비 = 착용하면 항상 붙어 있는 상태들 — 유닛 생성 시부터, 전투 밖에서도)
```

### 4.1 카드 사용 흐름

```
can_play(user, card, targets)
  → 모든 conditions 통과?  (근접 대상 존재 등)
  → 모든 costs 지불 가능?  (SP 충분, 상태 수치 충분)

play(user, card, targets)
  1. 이벤트 BEFORE_CARD_PLAYED
  2. costs 차례로 지불 → 지불한 양을 CardPlay.values 에 기록
  3. effects 차례로 실행 (CardPlay 를 넘김)
  4. 카드를 버린 카드 더미로
  5. 이벤트 AFTER_CARD_PLAYED
```

- **사용 불가 카드**: UI는 `can_play` 결과로 비활성 표시를 한다. 실패 이유도 돌려줘서 툴팁에 쓸 수 있게 한다.
- **카드 대체** (2026-11-04 사용자 확정): **손패에 있는 동안만** 대체 카드로 보이고 대체 카드로 사용된다. 사용한 뒤 묘지(버린 더미)나 제외로 갈 때는 **원래 카드**로 돌아간다. 덱에도 원래 카드가 있다. 대체 여부는 그때그때 사용자의 상태(`replacements`)로 판단하므로, 손패에 있는 도중 상태가 사라지면 원래 카드로 돌아온다 — *뒤 문장은 설계자 판단*

### 4.2 비용 (`CardCost`)

| 부품 | 필드 | 동작 |
|---|---|---|
| `SpCost` | `amount` | SP가 amount 이상이어야 사용 가능. 지불 시 차감 |
| `StatusCost` | `status`, `amount`, `consume_all`, `min` | 고정: 수치 ≥ amount 필요, amount 소모. 전부: 수치 ≥ min 필요, 전부 소모. 소모량을 `values["consumed:<status id>"]`에 기록 |

- `CardData`는 아직 저장소에 없으므로 새로 만든다. 필드 이름과 값은 **웹 카드 에디터의 내보내기 형식에 맞춘다** (나중에 변환기를 만들 때 다시 만들지 않기 위함):
  - `id`, `deck`(null이면 공용), `name {ko, en}`, `description {ko, en}`, `sp`, `cost`
  - `category`: `attack` / `skill` / `special` / `enemy`
  - `attackType`: `melee` / `ranged` / `ally` / `self`
  - `area`: `[[x, y], ...]` (−2..2, 비어 있으면 단일)
  - `keywords`: 키워드 id 배열, `art`: 그림 경로, `upgrades`: 같은 필드를 가진 강화 단계 배열(최대 5)
  - GDScript 쪽 이름은 snake_case(`attack_type`)로 쓰되 값은 위와 같게 둔다.
- 카드 데이터의 기존 `sp` 필드는 `SpCost`와 겹친다. **`sp` 필드를 그대로 두고, 카드를 쓸 때 자동으로 SP 비용으로 취급한다** (에디터와 호환하기 위함). `costs`에는 SP 외의 추가 비용만 넣는다 — *설계자 판단*

### 4.3 조건 (`CardCondition`)
- `MeleeTargetExists`: 공격 종류가 근접이면 자동으로 붙는 기본 조건
- `HasStatus { status, min }`: 소모 없이 수치만 확인
- 새 조건은 하위 클래스로 추가한다.

### 4.4 효과 (`CardEffect`)

모든 효과는 `apply(play: CardPlay) -> void`를 구현한다. 대상은 `target` 필드(`AREA`, `SELF`, `ALL_ALLIES`, `ALL_ENEMIES` 등)로 정한다.

| 부품 | 내용 |
|---|---|
| `DamageEffect` | 공격 스탯 × % × 배율. 치명 판정. 방어도 먼저 깎고 남은 만큼 HP. 스태미너도 깎음 |
| `BlockEffect` | 방어 스탯 × % × 배율만큼 방어도 |
| `HealEffect` | 공격 스탯 × % × 배율만큼 회복 |
| `ApplyStatusEffect` | 상태 부여 (`status`, `stacks`) |
| `ModifyStacksEffect` | 상태 수치 증감 (자연 감소, 절반 감소 등) |
| `DrawEffect` | 카드 N장 드로우 |
| `ScriptEffect` | 전용 스크립트 실행 (예외용) |

**배율(`ValueSource`)**: 효과 수치에 곱하는 값. 기본은 1.
- `Fixed(n)`
- `Consumed(status)`: 이번 카드 사용에서 소모한 상태 수치
- `StackCount(status, who)`: 현재 상태 수치
- 필요하면 하위 클래스로 추가 (예: 잃은 HP 비율)

**예시: 핏방울을 전부 소모해서 공격**
```
CardData "피의 참격"
  sp: 2
  costs:   [StatusCost { status: 핏방울, consume_all: true, min: 1 }]
  effects: [DamageEffect { percent: 40, target: AREA,
                           multiplier: Consumed(핏방울) }]
→ 공격 100, 핏방울 5 소모  →  100 × 40% × 5 = 200 피해
```

### 4.5 상태 (`StatusData`)

버프, 디버프, 패시브는 모두 `StatusData`다. 태그(`BUFF` / `DEBUFF` / `PASSIVE`)로만 구분한다.

- **수치(stacks)**: 상태마다 정수 수치를 가진다. 0이 되면 상태가 제거된다 (패시브는 수치를 쓰지 않으면 계속 유지).
- **수치 감소 규칙은 상태마다 다르다** (사용자 결정). 공통 감소 시스템이나 지속 턴 시스템을 두지 않고, 각 상태가 자기 트리거로 정의한다. 예: "차례 종료 시 수치 1 감소", "피격 시 절반", "감소 없음" 등
- **triggers**: `StatusTrigger { event, filter, effects }`
  - `event`: 아래 이벤트 중 하나
  - `filter`: 이 상태의 주인이 이벤트의 어떤 역할일 때 반응하는지 (`OWNER_IS_ACTOR`, `OWNER_IS_TARGET`, `OWNER_IS_ALLY_OF_ACTOR` 등)
  - `effects`: `CardEffect` 그대로 재사용
- **modifiers**: `StatModifier { stat, kind: PERCENT | FLAT, value: ValueSource }`
  - 값이 다른 것에 따라 변할 수 있음 (피의 갈망: 잃은 HP 비율)
- **replacements**: `{ 원본 CardData: 대체 CardData }`

**노션 버프 목록을 이 구조로 표현한 예**

| 상태 | 표현 |
|---|---|
| 출혈 | trigger: `DRAW_PHASE` / `OWNER_IS_ACTOR` → `DamageEffect`(고정값 = 수치) |
| 혈갑 | trigger: `TURN_END` / `OWNER_IS_ACTOR` → `BlockEffect`(배율 = 수치) |
| 핏방울 | trigger: `DAMAGE_TAKEN` / 필터 `TARGET_IS_ENEMY_OF_OWNER`(적이 받은 피해, 누가 걸었든) / 출처 "bleed" → `ModifyStacks`(+피해량) — 2026-11-04 사용자 확정 |
| 혈갑: 공격태세 | modifier: 공격 +%(배율 = 혈갑 수치), replacements: 혈갑 해체 카드 → 피의 참격 |
| 피의 갈망 | modifier: 공격 +%(배율 = 잃은 HP 비율), trigger: `DAMAGE_DEALT` → 회복·혈갑 부여 |

정확한 수치와 "공격을 한 번 더"(혈갑: 공격태세) 같은 세부 규칙은 기획이 정해지는 대로 데이터로 채운다. "한 번 더 공격"처럼 부품으로 안 되는 것은 `ScriptEffect`로 처리한다.

- 고정 피해(출혈)는 공격 스탯 × %가 아니라 **고정값 피해**다. `DamageEffect`에 `flat` 모드를 두어 스탯을 거치지 않게 한다.
- 고정 피해도 **일반 피해 규칙을 그대로 따른다** (사용자 결정): 방어도에 막히고, 치명 판정을 하고, 스태미너를 깎고, `DAMAGE_DEALT`/`DAMAGE_TAKEN`을 발행한다. 그래서 피의 갈망·핏방울도 출혈 피해에 반응한다. 계산에서 스탯 × % 대신 고정값을 쓰는 것만 다르다.

**부여자와 중첩** — *설계자 판단*
- 같은 상태가 다시 붙으면 **수치를 하나로 합친다** (부여자별로 나누지 않음).
- `StatusInstance`는 **마지막으로 부여한 유닛**(`applier`)을 기억한다.
- 상태의 트리거가 일으킨 효과에는 **행위자가 없다**(`actor = null`). `applier`는 기억만 해서 이벤트의 `applier` 칸에 기록되고, 필터 `OWNER_IS_APPLIER`("주인이 그 상태를 건 유닛일 때")로 쓸 수 있다. 수치 계산은 주인의 스탯으로 한다. (2026-11-04 사용자 결정으로 수정 — 이전 설계는 applier 를 행위자로 봤음)
- 이벤트에는 출처(`source`: 어떤 카드나 상태에서 나왔는지)를 담는다. 이를 위해 아래 두 가지를 추가한다.
  - **출처 필터**: `filter`에 "출처가 특정 상태일 때만" 조건을 추가 (핏방울: 출혈 피해에만 반응)
  - **이벤트 값 배율**: `ValueSource`에 `EventAmount` 추가 (핏방울: +피해량)

### 4.6 이벤트 (`BattleEvents`)

전투 하나에 하나씩 있는 이벤트 관리자. Godot signal을 그대로 쓰지 않고 직접 만든다. 구독 해제, 연쇄 제한, 정보 전달을 통제하기 위해서다.

**이벤트 목록**
- 전투: `BATTLE_START`, `BATTLE_END`, `ROUND_START`, `ROUND_END`
- 차례: `TURN_START`, `DRAW_PHASE`, `STANDBY_PHASE`, `END_PHASE`, `TURN_END`
- 카드: `BEFORE_CARD_PLAYED`, `AFTER_CARD_PLAYED`, `CARD_DRAWN`, `CARD_DISCARDED`
- 전투 행동: `DAMAGE_DEALT`, `DAMAGE_TAKEN`, `HEALED`, `BLOCK_GAINED`, `BLOCK_RESET`, `STATUS_APPLIED`, `STATUS_REMOVED`, `UNIT_MOVED`, `UNIT_DIED`, `STAMINA_BROKEN`
- 순서: `TURN_ORDER_CHANGED`

**규칙**
- 이벤트에는 `BattleEvent { type, actor, target, card, amount, source }`를 담아 보낸다. 구독자는 `filter`로 자기와 관련 있는지 판단한다.
- 같은 이벤트의 구독자는 **구독한 순서**대로 실행한다.
- 이벤트 처리 중에 구독이 추가·해제되면, 그 변경은 **다음 발행부터** 반영한다. 지금 도는 목록은 발행 시작 시점의 복사본을 쓴다.
- 상태가 제거되면 그 상태의 구독은 자동으로 해제된다. 상태가 실행 대기 중이었어도 이미 제거됐다면 건너뛴다.
- 이벤트가 이벤트를 부르는 **연쇄 깊이 상한**을 둔다 (기본 10). 넘으면 더 발행하지 않고 경고를 남긴다.

### 4.7 스탯 계산 (`StatBlock`)
- 기본값(캐릭터 데이터) + 상태의 `modifiers`를 모아서 3.4의 공식으로 계산한다. 장비 상태는 유닛을 만들 때부터 붙어 있다(**착용하면 항상 적용**, 2026-11-04 사용자 결정).
- 값을 저장해 두지 않고, 필요할 때 계산한다 (피의 갈망처럼 HP에 따라 바뀌는 보정이 있으므로) — *설계자 판단*. 성능 문제가 생기면 그때 캐시를 붙인다.
- 속도는 굴린 값에 보정을 적용해서 구한다(`BattleUnit.action_speed`). 상태가 붙거나 떨어질 때 남은 행동의 속도를 다시 계산해서, 바뀌었으면 `TurnOrder`에 재정렬을 요청한다.

### 4.8 턴 순서 (`TurnOrder`)
- 이번 라운드 남은 **행동** 목록을 속도 내림차순으로 유지한다. 행동 = (유닛, 몇 번째 행동). 라운드 시작 시 각 유닛이 행동 횟수만큼 속도를 굴려 행동들을 넣는다.
- 재정렬 요청이 오면 남은 유닛만 다시 정렬한다.
- 속도가 같으면 아군 먼저, 그다음 전투 시작 시 배치 순서, 그다음 행동 순번 — *설계자 판단*
- 죽은 유닛은 목록에서 뺀다.

### 4.9 적
- 적도 `BattleUnit`이고 같은 카드 규칙을 쓴다.
- 적의 차례도 **아군과 같은 순서**(차례 시작 → SP 회복 → 드로우 페이즈 → 대기 → 행동 → 엔드 → 종료)로 진행하고, 같은 이벤트를 발행한다. 그래야 적에게 걸린 출혈·혈갑도 똑같이 발동한다 — *설계자 판단*
- 차이는 드로우와 행동뿐이다. 적은 드로우 페이즈에 1장을 뽑고, 행동 단계에서 그 1장을 쓴다.
- 쓸 수 없는 카드(근접 대상 없음, SP 부족 등)를 뽑으면 그 차례는 행동하지 않고 넘어간다. 보스는 순서상 다음 카드로 넘어간다 — *설계자 판단*
- 일반 적: 자기 차례에 자기 덱에서 한 장을 뽑아 사용한다.
- 보스: 정해진 카드 순서를 차례대로 사용하고, 끝까지 쓰면 처음으로 돌아간다 — *설계자 판단*
- 적의 대상 선택은 이번 범위에서는 단순 규칙(근접은 규칙대로, 원거리는 무작위)으로 둔다. 어그로 규칙이 정해지면 교체한다.

## 6. 테스트

- 전투 로직은 화면 없이 돌아가야 한다. `BattleManager`를 씬 없이 만들고 유닛을 넣어 테스트할 수 있어야 한다.
- 난수(치명타, 셔플, 적 선택)는 시드를 주입할 수 있게 한다.
- 최소 테스트 목록
  - 비용: SP 부족 / 상태 수치 부족 시 사용 불가, 고정·전부 소모량 기록
  - 배율: 소모량 비례 피해 계산 (내림, 최소 1)
  - 스탯: % 먼저 고정값 나중, % 합산
  - 턴: 행동마다 속도 굴림, 속도 순, 감속 디버프 후 즉시 재정렬, 이미 쓴 행동 제외, 행동 횟수 2 면 한 라운드 두 차례
  - 이벤트: 구독 순서 실행, 처리 중 해제, 연쇄 상한
  - 상태: 출혈(드로우 시 피해), 혈갑(차례 종료 시 방어도)
  - 카드 대체
  - 방어도 먼저 소모 후 HP, 스태미너는 막힌 양 포함 전체 피해만큼 감소
  - 피해를 가한 쪽 스태미너가 가한 피해의 절반(내림)만큼 회복, 최대치 초과 없음
  - 라운드 시작 시 방어도 초기화
  - 이동: 이동속도만큼만, 다른 유닛 칸 통과 불가, 이동 후 근접 카드 사용 가능 여부 갱신
  - 엔드 페이즈 손패 전부 버림, 덱이 비면 버린 카드를 섞어 덱으로

## 7. 설계자에게 맡기는 것

- 테스트 프레임워크 선택 (GUT 또는 gdUnit4)
- 클래스 이름과 세부 필드 이름
- 드로우 장수 (캐릭터 데이터 값으로 두고 기본 5장)
- 덱이 비었을 때: 버린 카드 더미를 섞어서 덱으로
- 연쇄 깊이 상한 값

## 8. 미정 (기획 결정 필요, 구현은 자리만 마련)

- 스태미너가 0일 때 부여할 상태의 효과
- 방어도 초기화의 예외가 되는 "특정 상황"의 구체 규칙
- 각 상태(출혈, 혈갑 등)의 구체적인 수치 감소 규칙 (구조는 트리거로 준비됨)
