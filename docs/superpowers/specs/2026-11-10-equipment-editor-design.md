# 장비 에디터 — 웹 에디터에서 장비 만들기 → Godot 가져오기 (설계)

날짜: 2026-11-10 · 상태: 검토 대기

## 왜

지금은 장비(`EquipmentData`)를 Godot 인스펙터에서 상태(StatusData) + 보정(StatModifier)을 손으로 조립해야 한다 (예: `statuses/equipment/test_sword.tres`). 카드는 웹 카드 에디터(아티팩트 "Project Void 카드")에서 만들고 zip 으로 Godot 에 가져오는데, 장비도 **카드와 똑같은 흐름**으로 만들고 싶다.

## 목표

- 웹 카드 에디터에 **장비** 탭을 추가해 장비를 만들고 고친다.
- 장비가 가진 것:
  - 이름(한·영), 설명(한·영), 그림
  - **종류**: 무기 / 방어구 / 장신구 (고정 3개, 사용자 결정)
  - **등급**: 노말 / 레어 / 유니크 / 유물 (고정 4개, 노션 아이디어 박스와 같음)
  - **스탯**: 줄 여러 개. 한 줄 = [스탯] [고정값(+) 또는 %] [수치]. 예) `공격 +5`, `속도 +10%`. 음수 허용 (사용자 결정: 고정·% 둘 다)
  - **키워드**: 카드와 **같은** 키워드 목록(`keywords` 컬렉션)에서 고른다. 마우스를 올리면 카드처럼 오른쪽에 키워드 설명이 뜬다
- **특별한 버프·특수 효과**는 웹에서는 **설명 글로만** 적는다. 실제 동작은 Godot 에서 장비 `.tres` 의 `statuses` 에 상태를 붙인다 (카드의 effects 와 같은 분담, 사용자 결정).
- 내보내기 zip 에 장비가 같이 들어가고, Godot **카드 가져오기**가 장비 `.tres` 도 만들거나 갱신한다. 다시 가져와도 Godot 에서 붙인 `statuses` 는 유지된다.
- 반대 방향(Godot **카드 내보내기** → 웹 **가져오기**)도 장비를 포함한다. 카드와 같이 추가·변경만, 삭제 없음.
- 가져온 장비의 스탯이 실제 게임 스탯에 반영된다 (착용하면 항상 적용 — 기존 규칙).

## 하지 않는 것 (이번 범위 밖)

- 장비 강화 단계, 숙련도, 등급에 따른 수치 자동 계산 (노션에서 아직 미정)
- 버프·특수 효과를 웹에서 고르는 기능
- 게임 안 장비 화면(착용·교체 UI), 상점·보상에 장비 등장
- 종류별 착용 칸 제한 (무기 1개 등) — 종류는 지금은 분류·표시용

## 실패로 보는 것

- 다시 가져왔더니 Godot 에서 붙인 장비 상태가 사라짐
- 장비를 가져오면서 기존 카드·키워드 가져오기 동작이 바뀜
- 장비 파일 이름·폴더가 바뀌면서 유닛(`UnitData.equipment`)의 참조가 끊김 (카드처럼 파일을 옮겨서 uid 유지)
- 웹에서 만든 적 없는 기존 장비(`test_sword.tres`, id 없음)가 가져오기 때문에 지워짐

## 정해진 것

### 웹 에디터 (아티팩트 https://claude.ai/artifact/T2zETQHPfWew1HejtgHKHd)
- 상단 탭: 공용 카드 / 덱 / 키워드 / **장비**
- 장비 탭: 카드 그리드처럼 장비 타일 그리드 + 필터(종류, 등급) + 이름 검색. "새 장비" 버튼
- 편집은 카드처럼 오른쪽 시트 + 미리보기
- 등급은 테두리 색으로 구분 (카드 분류 색처럼)
- 데이터는 같은 artifact db 의 새 컬렉션 `equipment`. 그림은 카드와 같은 assets
- 키워드 탭의 "사용 수"에 장비가 쓰는 것도 센다 (키워드를 지울 때 장비에서 쓰는지 보이도록)

### zip 형식 (`cards.json` 에 키 추가)
```json
"equipment": [{
  "id": "...",
  "name": {"ko": "", "en": ""},
  "description": {"ko": "", "en": ""},
  "slot": "weapon" | "armor" | "accessory",
  "rarity": "normal" | "rare" | "unique" | "relic",
  "stats": [{"stat": "attack", "kind": "flat" | "percent", "amount": 5}],
  "keywords": ["kw_id"],
  "art": "art/<파일>" | null
}]
```
- `stat` 값: `hp, sp, attack, defense, speed, move, crit_rate, crit_damage, aggro, stamina, actions` (= `BattleTypes.Stat` 순서·이름)
- `equipment` 키가 없는 예전 zip 도 그대로 읽힌다 (장비는 아무것도 안 바뀜)

### Godot
- 저장 위치: `res://statuses/equipment/<종류 폴더>/<장비 이름>.tres` (종류 폴더 = `weapon`/`armor`/`accessory`). 이름 겹치면 `_<id>`. 찾을 때는 파일 안의 id 기준 (카드와 같은 규칙)
- `EquipmentData` 에 웹 담당 칸을 추가: `id`, 이름·설명(한·영), `slot`, `rarity`, `stats: Array[StatModifier]`, `keywords`, `art`
- 기존 `statuses` 칸 = Godot 담당 (버프·특수 효과). 가져오기가 건드리지 않는다
- 웹 스탯(`stats`)은 `statuses` 와 따로 저장하고, 착용 시 기존 장비 상태와 같은 방식으로 항상 적용된다
- 가져오기의 삭제 규칙: **id 가 있는 장비 파일만** 관리한다. zip 에 없는 id 장비는 지우고(미리보기에 표시, Godot 상태가 붙어 있으면 ⚠), id 없는 예전 파일(`test_sword.tres`)은 건드리지 않는다
- **착용 중인 장비는 지우지 않는다** (사용자 결정): zip 에 없지만 `res://entities/units/` 의 어떤 `UnitData.equipment` 가 참조하면 파일을 남기고, 미리보기에 "<유닛 이름> 착용 중이라 남김" 으로 표시한다
- 장비 그림: `res://statuses/equipment/art/` (내 판단). 카드 그림 폴더(`cards/art/`)와 분리해서 기존 카드 그림 정리 규칙을 건드리지 않는다. 이 폴더의 안 쓰는 그림은 장비 가져오기가 정리한다
- 원래 % 단위인 스탯(치명확률·치명피해 등)도 공식은 그대로 (내 판단): 고정 `+10` = 10%p 증가, `+10%` = 기본값에 곱함(기본 0 이면 효과 없음). 웹에서 이런 스탯에 % 를 고르면 그 뜻을 안내 문구로 보여 준다
- 메뉴는 기존 "카드 가져오기... / 카드 내보내기..." 그대로, 미리보기 창에 장비 추가·변경·삭제가 함께 나온다

## 빌더에게 맡기는 것
- 장비 타일의 정확한 모양, 스탯 줄 편집 UI 세부
- `EquipmentData` 의 기존 `display_name` 을 `name_ko` 로 바꿀지 유지할지 (바꾸면 `test_sword`·테스트 같이 정리)
- 웹 스탯을 스탯 계산에 넣는 방법 (장비 하나당 숨은 패시브 상태로 붙일지, `get_stat` 계산에 직접 더할지) — 기존 공식 `floor(기본 × (1 + %합/100)) + 고정합` 을 그대로 따를 것
- 기존 GUT 테스트·웹 에디터 Node 테스트 방식(CardModel 순수 로직 분리) 따르기
