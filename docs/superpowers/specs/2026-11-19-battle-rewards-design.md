# 전투 보상 목록 (클릭해서 챙기기) — 설계

2026-11-19

## 왜
지금은 의뢰 전투에서 이기면 공허 조각이 자동으로 들어가고, 아이템은 받기/넘어가기 버튼, 카드 보상은 없다.
슬더스처럼 승리 후 **보상 목록을 한 줄씩 클릭해서 챙기는** 방식으로 바꾸고, 그 목록에 **카드 보상**을 새로 넣는다.

## 목표
- 의뢰 전투 승리 → 결과 창에 보상 목록. 줄을 누르면 그 보상을 챙기고 줄이 사라진다
- 보상 종류
  - **공허 조각** `BattleData.shard_reward` — 누르면 지갑으로 (일반·보스)
  - **소비 아이템** — 지금과 같은 확률(`item_drop_chance`)·후보. 누르면 가방으로. 가방이 가득 차면 바꿀 칸 고르기 / 취소(줄은 남음)
  - **카드 추가** (일반 전투만) — 누르면 카드 3장 창. 1장 고르면 그 카드 주인 캐릭터의 **의뢰 덱**(`run_deck`) 맨 뒤로, 줄 사라짐. "넘어가기"는 창만 닫고 줄은 남음
- **계속** 버튼은 언제나 누를 수 있다. 안 챙긴 보상은 사라진다

## 카드 보상 규칙 (사용자 결정: A)
- 후보 = 살아 있는 파티원 캐릭터의 카드 전체 (상점과 같은 `CardPool.cards_for`, 공용·적 전용 제외), 겹치지 않게 3장 (`BattleScreen.card_reward_count`, 기본 3)
- 카드마다 주인 캐릭터 표시, 고르면 그 주인의 의뢰 덱으로. `UnitData.deck` 원본은 안 바꿈
- 후보가 하나도 없으면 카드 보상 줄을 만들지 않는다
- 보스 전투: 카드 보상 없음 (의뢰가 끝나 의뢰 덱이 사라지므로) — **내 판단**, 나중에 바꾸기 쉬움
- 3장은 승리 때 정해 둔다 (창을 닫았다 다시 열어도 같은 3장)

## 아님 (이번에 안 함)
- 카드 등급·희귀도, 카드 보상 다시 뽑기, 보상 연출(날아가는 애니메이션)
- F6 시험 전투 보상 (지금처럼 없음, "다시 하기" 그대로)
- 패배 시 보상 (없음)

## 접근 (사용자 결정: 1번)
1. **전투 결과 창 안에 보상 목록** ← 선택. 전투 자리에서 바로 챙기는 느낌, 기존 아이템 받기 흐름이 이미 결과 창에 있음
2. 별도 보상 화면 씬 — 화면 전환이 늘고 전투 배경이 사라져서 제외

## 구조
- `Scripts/stage/battle_reward.gd` (`BattleReward`, RefCounted, 순수 로직 · 테스트 대상)
  - 승리 때 만든다: 조각 수, 아이템(없을 수 있음), 카드 후보 3장 + 주인
  - `claim_shards(wallet)`, `claim_item(inventory)` / `swap_item(inventory, index)`, `claim_card(index)` — 챙기면 그 보상은 비워짐. 실패(가방 가득 등)면 false, 아무것도 안 바뀜
  - 카드 후보 고르기는 상점 `_stock_cards` 와 같은 규칙 → 공용 함수로 뽑아서 둘이 같이 쓴다 (`CardPool` 쪽)
- 보상 한 줄 = 결과 창 안 템플릿 버튼(`RewardTemplate`)을 보상 개수만큼 duplicate (상점의 `UnitTabTemplate` 과 같은 방식 — 줄이 버튼 하나뿐이라 따로 씬을 만들 만큼은 아님, 계획 단계에서 바꿈)
- 결과 창(`battle_screen.tscn` ResultOverlay)
  - DropBox → 보상 목록(RewardList) + 가방 가득 찼을 때 바꿀 칸(지금 DropSlots 재사용)
  - 카드 선택 창(CardPick): CardView 3개 + 주인 이름 + "넘어가기"
  - 노드는 에디터(MCP)로 만든다
- `battle_screen.gd`: `_show_result` 에서 조각 자동 지급 제거, `BattleReward` 만들고 목록 그리기. 계속 버튼은 항상 보임

## 빌더에게 맡김
- 줄 글자·아이콘 모양, 카드 선택 창 배치
- 키보드 조작(포커스 이동)은 기본 버튼 포커스 수준
