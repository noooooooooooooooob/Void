# 전투 격자판 칸 모양 (원근 사각형) 설계

2026-11-11. 상태: 사용자 승인. 전투 크기가 5×5 보다 작을 때는 지금 규칙(맞닿는 쪽 열, 가운데 행, 칸 크기 고정)을 유지하기로 확정.

## 왜

격자판 칸이 정사각형이라 배경 그림의 돌바닥과 어울리지 않는다. 배경 원근을 따라 안쪽 칸일수록 작아지고 모이는 모양으로 깔고 싶다. 배경마다 바닥이 다르므로 에디터에서 직접 맞출 수 있어야 한다.

## 사용자가 정한 것

- 모양은 **바닥 원근** (시안 A). 평행사변형·쿼터뷰 마름모가 아니다.
- 조정 방식 두 가지를 다 만든다.
  - **기본:** 보드 전체의 네 모서리를 바닥에 맞추면 칸이 원근대로 자동으로 나뉜다.
  - **필요할 때:** 칸 하나의 꼭짓점을 직접 옮긴다.

## 목표

1. 칸이 네 꼭짓점을 가진 임의의 사각형으로 보인다.
2. 칸 색, 이동·대상·범위 표시, 클릭 판정이 모두 그 모양을 따른다. 사각형 바깥 귀퉁이는 눌리지 않는다.
3. 에디터 2D 화면에서 핸들을 드래그해 조정한다. 실행 취소가 된다.
4. 아군·적 보드는 따로 맞춘다. 배경 씬마다 값이 따로 저장된다.

## 하지 않는 것

- 전투 규칙·격자 좌표·칸을 켜는 규칙(맞닿는 쪽 열, 가운데 행) 변경
- 보드가 없는 배경의 기본 격자 변경 (지금처럼 네모)
- 칸에 그림을 입히는 기능, 유닛 박스 왜곡

## 구조

### 데이터

- `BattleBoard.corners: PackedVector2Array` — 보드 네 모서리, 판 기준 좌표. 순서는 왼쪽 위, 오른쪽 위, 오른쪽 아래, 왼쪽 아래.
- `BattleBoard.cell_gap: float` — 칸 사이 틈 비율 (칸 피치 대비, 0 이상 0.5 미만).
- `GridCell.custom_corners: PackedVector2Array` — 직접 잡은 꼭짓점, 판 기준 좌표. **비어 있으면 자동.**
- `GridCell` 의 런타임 모양 `quad` — 칸 기준 좌표. 비어 있으면 칸 네모 전체 (기본 격자용).

### 자동 분할

보드 네 모서리로 단위 정사각형 → 사각형 호모그래피(투영 변환)를 구한다. 선형 보간이 아니라 호모그래피여야 안쪽 칸이 실제로 작아진다. 칸 (열, 행) 의 네 꼭짓점은 단위 좌표 `(열/5, 행/5)` 칸을 `cell_gap` 만큼 줄여서 변환한다. 이 계산은 순수 함수로 두어 테스트한다.

### 칸 배치

`BattleBoard` 가 `_ready` 와 `corners`·`cell_gap`·`custom_corners` 가 바뀔 때 각 칸을 배치한다. 칸 Control 의 위치·크기는 사각형의 경계 상자로 맞추고, `quad` 는 그 안의 좌표로 넘긴다. 칸의 offset 값은 계산 결과일 뿐 원본이 아니다.

### 칸 그리기·클릭

- `GridCell` 은 `_draw` 로 사각형을 채우고 표시 색을 덧칠한다. `ColorRect` 와 `Mark` 자식은 사각형을 못 그리므로 `Control` + `@export` 색으로 바꾼다. `set_mark`·`mark_color` 는 그대로 둔다.
- `_has_point` 를 재정의해 `Geometry2D.is_point_in_polygon` 으로 판정한다. 경계 상자가 겹쳐도 정확한 칸이 눌린다.
- `center()` 는 네 꼭짓점의 평균을 돌려준다. `battle_screen.gd` 의 유닛 박스 배치(지금 `cell.size` 기준)를 이것으로 바꾼다.
- 에디터에서 보이도록 `GridCell`·`BattleBoard` 는 `@tool`.

### 에디터 플러그인

새 플러그인 `addons/board_shape_editor` (`_forward_canvas_draw_over_viewport`, `_forward_canvas_gui_input`).

- `BattleBoard` 선택: 네 모서리 핸들. 드래그하면 자동 칸이 따라온다.
- `GridCell` 선택: 그 칸의 네 꼭짓점 핸들. 처음 드래그하면 현재 모양을 `custom_corners` 로 복사하고 직접 조정 칸이 된다.
- 자동으로 되돌리기: 인스펙터에서 `custom_corners` 를 비우면 된다 (전용 버튼 없음).
- 변경은 `EditorUndoRedoManager` 로 기록한다.

배경 씬의 보드는 이미 "자식 편집 가능"이므로 칸 값도 배경 씬에 저장된다.

## 구현자 판단 (사용자가 정하지 않음, 제안자 결정)

- **보드 네 모서리는 5×5 전체의 테두리다.** 3행 전투는 가운데 3행만 쓰므로 실제로 보이는 칸은 테두리보다 안쪽에 있다.
- `mountain_shrine.tscn` 의 시작 값은, 기본 전투(3행 × 4열)에서 켜지는 칸이 시안 A 자리에 오도록 계산해 넣는다.
- 유닛 박스는 100×100 그대로 똑바로 세워 칸 중심에 둔다. 안쪽 작은 칸에서는 칸 밖으로 나올 수 있다.
- `cell_gap` 기본값은 지금 틈과 같은 10/130.
- `battle_board.tscn` 의 기본 `corners` 는 5×130 = 650 정사각형. 지금 배치와 틈 위치가 몇 px 다를 수 있어 `test_cells_have_no_minimum_and_start_at_120_in_place` 는 새 배치에 맞게 고친다.

## 제약

- `.tscn` 변경과 `project.godot` 의 플러그인 켜기는 에디터를 끈 상태에서 Godot 헤드리스로 저장한다. 저장 뒤 씬 맨 위 `uid` 가 지워지지 않았는지 확인한다. GoPeak `scene-node-set` 은 인스턴스가 있는 씬을 망가뜨리므로 쓰지 않는다.
- 테스트는 프로젝트 복사본에서 MCP 를 끄고 실행한다.
- 구현 전 `mountain_shrine.tscn` 에 사용자가 칸을 옮긴 값이 있는지 확인한다. 있으면 덮어쓰기 전에 알린다.

## 확인 방법

- GUT: 호모그래피 (네 모서리 일치, 안쪽 칸이 더 작음), 칸 분할, `custom_corners` 우선, `_has_point` (안쪽 참, 귀퉁이 거짓), `center`, 기본 격자 칸은 네모 유지.
- 핸들 드래그는 헤드리스로 확인할 수 없어 사용자가 에디터에서 직접 확인한다.
