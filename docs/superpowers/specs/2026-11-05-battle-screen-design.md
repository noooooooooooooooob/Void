# 전투 화면 (시험판) 설계

작성 2026-11-05 · 브랜치 `feat/battle-system`

## 1. 왜 만드는가

전투 로직(Task 1~10)은 테스트로만 확인됐다. 사용자가 **직접 홍연을 조작해서 전투 한 판을 처음부터 승리/패배까지** 해 보면서 규칙과 흐름이 맞는지 눈으로 확인하려는 것이 목적이다.

- 성공: 씬을 열고 F6 → 카드를 골라 쓰고, 이동하고, 차례를 넘기고, 적이 행동하는 것을 보고, 한쪽이 전멸하면 결과가 뜨고 다시 할 수 있다.
- 비목표: 그림·연출 완성도, 의뢰/월드맵 연결, 홍연 고유 카드(효과 미정), 예상 피해 표시, 적 의도 표시(적은 차례에 카드를 뽑아서 쓰므로 미리 정해진 의도가 없음), 일시정지·설정.
- 실패로 보는 것: 화면이 규칙과 다르게 동작하는 것(예: 쓸 수 없는 카드가 써짐, 행동 순서 표시가 실제와 다름). 화면 쪽에서 규칙을 따로 계산하지 말고 반드시 `Battle` 의 판정(`can_play`, `melee_target`, `path_length`, `area_targets` …)을 쓴다.

## 2. 판 구성 (데이터)

- 카드: 공용 `타격`(근접, 공격 100%), `사격`(원거리, 공격 100%), `방어`(자신, 방어도 100%) **세 장만** 쓴다. 효과는 이 세 카드 `.tres` 에 실제로 붙인다(DamageEffect / BlockEffect). 리소스 안에 리소스를 넣는 작업이라 MCP 로 안 되므로 인스펙터 안내 또는 에디터를 끈 상태에서 Godot 이 저장.
- 아군: **시험용 홍연** 유닛 1명(새 `.tres`, 홍연 숫자 스탯만 복사, 원래 홍연 덱 10장은 그대로 둔다). 덱 = 타격 4 · 사격 3 · 방어 3. **패시브(피의 갈망)·장비(시험용 검)는 붙이지 않는다** — 피해가 "공격 × 100%" 그대로 나와야 눈으로 규칙을 확인하기 쉽다. *(구현자 판단으로 정함)*
- 적: **시험용 적** 2마리, 같은 세 장으로 만든 덱. 스탯은 시연 전투 수준(HP 45, 공격 9, 방어 6, 속도 2~8). *(구현자 판단)*
- **전투 데이터 리소스 `BattleData`** (새 Resource, `Scripts/battle/battle_data.gd`): 격자 행 수, 편별 열 수, 아군 배치 목록, 적 배치 목록(각각 UnitData + 칸). 시험판은 `battles/test_battle.tres` 하나. 나중에 의뢰 전투에서 그대로 쓴다.
  - 배치 한 칸 = 작은 Resource `BattleSlot { unit: UnitData, cell: Vector2i }`.

## 3. 화면 배치 (Figma `Project Void UI Wireframes` v6 · 08-A 전투 HUD 기준)

1920×1080 기준, 그림 대신 단색 박스, 격자는 기울이지 않은 평면. *(구현자 판단)*

- 위 가운데: **라운드 번호**와 **행동 순서 초상화 줄**(남은 행동 순서대로, 지금 차례 강조, 아군/적 색 구분, 속도 숫자). 라운드 중 재정렬되면 즉시 갱신.
- 왼쪽: **아군 상태 패널**(이름, HP 바, 방어도, 스태미너, 상태 이름+수치). 오른쪽: **적 상태 패널** 같은 구성.
- 가운데: **아군 격자(왼쪽)와 적 격자(오른쪽)**. 칸마다 유닛 박스(이름, HP, 방어도). 죽은 유닛은 흐리게 또는 제거.
- 아래 가운데: **손패** — 기존 `CardView` 씬을 재사용(키워드 툴팁 포함). 쓸 수 없는 카드는 어둡게.
  - CLAUDE.md 확정 규칙 "전투 중엔 계산된 수치"에 따라, 손패 카드에는 **그 유닛 기준으로 계산된 수치**를 크게 표시한다(목업의 큰 숫자 자리). 첫 번째 피해/방어도/회복 효과의 `final_amount`(치명 제외) 값. 설명 문장(`description_ko`)은 그대로 둔다. `CardView` 에 "계산된 수치를 표시" 함수를 하나 더한다(갤러리·덱 편집에서는 부르지 않으므로 기존 표시는 그대로). *(구현자 판단)*
  - 비목표의 "예상 피해"는 대상을 가리켰을 때 대상의 HP 변화를 미리 보여 주는 것(목업 28 → 23)을 말한다.
- 왼쪽 아래: SP, 이동력, 덱 장수. 오른쪽 아래: 버린 더미·제외 더미 장수, **차례 종료** 버튼.
- **떠오르는 숫자**: 피해(빨강), 방어도(파랑), 회복(초록)을 유닛 위에 잠깐 띄운다.
- **전투 기록**: 한쪽 구석에 최근 몇 줄("공허 잔해 A: 타격 → 홍연 9"). 적 행동을 따라가기 위한 것(목업에는 없음). *(구현자 판단)*
- **결과 오버레이**: 승리/패배 글자 + "다시 하기"(같은 BattleData 로 새 전투).

## 4. 조작 (사용자 결정 포함)

아군 차례에만 입력을 받는다.

- **대상을 고르는 카드(원거리·아군)** — *사용자 결정: 슬레이 더 스파이어처럼 화살표로 가리킨다.* 카드를 클릭하거나 끌면 카드가 들어 올려지고 카드에서 마우스까지 **휜 화살표**가 따라온다. 고를 수 있는 유닛 위에 올리면 그 유닛과 광역 범위(`area_targets`)가 강조된다. 클릭(또는 끌던 손을 뗌) → 사용. 고를 수 없는 곳이면 아무 일 없음.
- **근접 카드**: 대상이 자동(`melee_target`)이므로 화살표가 그 적에게 고정된다. 클릭하면 사용. 근접 대상이 없으면 카드가 어둡게 표시되고 고를 수 없다. *(구현자 판단)*
- **자신 카드**: 화살표 없음. 카드를 손패 위쪽으로 끌어 올리거나 고른 카드를 한 번 더 누르면 사용. *(구현자 판단)*
- 취소: 우클릭, 또는 ESC.
- **이동**: 카드를 고르지 않은 상태에서 갈 수 있는 아군 빈 칸(`path_length` ≤ 이동력)이 옅게 표시되고, 누르면 이동.
- **차례 종료** 버튼 → 엔드 페이즈.
- **적 차례**: 자동 진행. 행동 사이 약 0.7초 간격으로 눈으로 따라갈 수 있게 한다.

## 5. 구조

- **`BattleSession`** (새 RefCounted, `Scripts/battle/battle_session.gd`) — 화면과 `Battle` 사이의 진행 담당. 순수 로직이라 GUT 로 테스트한다.
  - `BattleData` → BattleUnit 생성 → `Battle` 생성·시작.
  - 나중에 의뢰에서 파티(이미 있는 아군 `BattleUnit`, HP 유지)를 넣을 수 있게, 세션 생성 시 **아군 유닛 목록을 밖에서 줄 수 있게** 한다. 주지 않으면 `BattleData` 의 아군 배치로 새로 만든다(시험판). `BattleData` 의 아군 배치는 시험·고정 전투용이고, 적 배치와 격자 크기가 본래 용도다. *(구현자 판단)*
  - 다음 차례 진행: `next_turn` → 아군이면 `begin_turn` 후 입력 대기 / 적이면 `run_enemy_turn`. 승패 확인.
  - 화면이 부르는 함수: `play(card, origin)`, `move(cell)`, `end_player_turn()`, `step()`(적 차례 하나 진행).
  - 화면에 알리는 시그널: 상태 변경, 차례 시작(누구), 결과.
  - 적 차례 간격(0.7초)은 화면 쪽 타이머가 `step()` 을 부르는 방식으로, 세션 자체는 시간과 무관하게 둔다(테스트 쉬움).
- **화면 씬** `ui/battle_screen/battle_screen.tscn` + `Scripts/ui/battle_screen.gd`. 반복 항목은 틀 씬을 만들어 instantiate: 격자 칸, 유닛 박스, 행동 순서 초상화, 상태 패널 한 줄, 떠오르는 숫자. 화살표는 `Line2D`(또는 `_draw` 베지어) 노드를 씬에 두고 스크립트가 점만 갱신.
- 모든 노드·배치·스타일은 에디터 씬 노드로 만든다(CLAUDE.md "Godot 에디터 우선"). 스크립트는 값 갱신과 입력 처리만.

## 6. 함께 고칠 것

- 작업 순서: 먼저 카드 파일 이름 변경(카드 가져오기 툴 수정)을 커밋한 뒤 시작한다. 공용 카드 효과·시험용 유닛은 새 파일 이름(`cards/data/common/타격.tres` 등)을 기준으로 한다.

- `Battle.start_round` 가 속도를 굴리기 **전에** `ROUND_START` 를 발행한다. 화면이 ROUND_START 에서 순서표를 그리면 틀린 순서가 나오므로, 순서 확정 뒤로 옮긴다(테스트 먼저).

## 7. 구현자에게 맡기는 것

색·크기·글꼴, 떠오르는 숫자 애니메이션, 전투 기록 줄 수, 초상화 모양, 화살표 곡선 모양, 시험용 적 이름·스탯 세부.
