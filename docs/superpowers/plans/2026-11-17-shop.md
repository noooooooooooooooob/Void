# 상점 (공허 조각·의뢰 덱·카드 구매/제거/강화·가방 버리기) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 의뢰 안 재화 공허 조각을 전투 승리로 모으고, 상점 노드에서 카드·소비 아이템을 사고 카드 제거·강화를 하며, 가방 아이템을 버릴 수 있게 한다.

**Architecture:** 규칙은 순수 로직에 둔다 — 지갑(`Wallet`), 카드 후보·원래 카드 찾기(`CardPool`), 상점 한 번의 진열·거래(`Shop`). `StageRun`(자동 로드)이 의뢰마다 지갑을 갖고, 덱 변경은 전투 유닛의 새 칸 `BattleUnit.run_deck`(의뢰 덱)에만 한다. 상점 화면(`shop_screen.tscn`)은 `Shop` 을 보여 주고 버튼을 이어 주기만 한다.

**Tech Stack:** Godot 4.7.2, GDScript, GUT 9.7.1

**Spec:** `docs/superpowers/specs/2026-11-17-shop-design.md`

## Global Constraints

- 공허 조각: 의뢰 안에서만, **의뢰가 끝나면 0**. 전투 승리(일반·보스) 때 `BattleData.shard_reward` 만큼. 처음 값 **일반 20 / 보스 50**
- 보스 노드는 **보스용 전투 데이터** `battles/boss_battle.tres` 를 쓴다 (적 구성은 `test_battle.tres` 와 같게 시작)
- 가격은 **모두 고정**, 이용할수록 오르지 않는다. 처음 값: 카드 구매 **50**, 소비 아이템 구매 **30**, 카드 제거 **75**, 카드 강화 **60**. 진열 카드 **5**, 진열 아이템 **3**. 모두 `ShopData`(`shop/shop_data.tres`)에서 바꿈
- 진열 카드: **지금 파티 캐릭터의 카드만**(카드 `deck_id` 가 그 캐릭터 덱 카드들의 `deck_id` 중 하나), 적 전용(`category == "enemy"`)·공용(`deck_id == ""`) 제외, 겹치지 않게. 산 카드는 **그 캐릭터의 의뢰 덱** 맨 뒤로
- 진열 아이템: `items/consumables/` 전부에서 무작위, **겹치지 않게** (후보가 적으면 있는 만큼). 가방이 가득 차면 못 삼
- **HP 0 으로 빠진 파티원은 상점에서도 빠진다**: 그 캐릭터의 카드는 진열되지 않고, 제거·강화할 덱으로 고를 수 없다 (상점에 넘기는 파티 = `StageRun.living_party()`)
- 카드 강화: 원래 카드의 `upgrades` 에서 **지금 카드를 뺀 것** 중 최대 3개(많으면 무작위 3개). 후보가 없으면 강화 불가. 고른 카드로 의뢰 덱의 그 칸을 바꿈
- 덱 변경(구매·제거·강화)은 **의뢰 덱에만**. `UnitData` 리소스는 절대 바꾸지 않는다
- 조각이 모자란 거래는 실패(아무것도 안 바뀜), 버튼은 흐리게(`disabled`)
- 상점에서 나가면 노드 클리어(`StageRun.complete_node()`), 다시 못 들어감
- 가방 아이템은 버릴 수 있다 (상점·전투 모두 가방 패널의 버리기)
- 장비 강화·전투 카드 보상·이벤트 조각은 만들지 않는다
- 프로젝트 규칙 (`CLAUDE.md`): 게임 스크립트는 `Scripts/` 아래, 씬은 `Scenes/` 아래, 데이터는 `.tres`. **`.tscn`/`.tres` 는 손으로 쓰지 않고 Godot 이 저장**한다 (에디터를 끈 상태의 헤드리스 스크립트, 또는 사용자가 에디터에서). 에디터가 켜진 동안 바깥에서 `res://` 의 `.tscn`/`.tres` 를 쓰지 않는다. 테스트는 프로젝트 복사본에서. 테스트 코드를 뺀 모든 스크립트에 한국어 주석(클래스 `##`, `@export`·공개 함수 `##`)
- 커밋은 사용자가 요청할 때만. 각 작업의 "커밋" 단계는 사용자 확인 뒤 실행

## Review Focus

1. 강화한 카드를 상점에서 다시 강화 → 원래 카드의 다른 강화만 뜨고, 강화가 1개뿐인 카드는 다시 강화 불가 (Task 3·4)
2. 같은 카드 두 장이 덱에 있을 때 한 장만 제거·강화 → 고른 칸(index)만 바뀜 (Task 4)
3. 파티원이 HP 0 으로 빠져 있음 → 그 캐릭터 카드는 진열되지 않고 제거·강화 대상 목록에도 없음. 모두 빠졌으면 카드 진열 0장 (Task 4·6)
4. 의뢰를 끝내고 새로 시작 → 조각 0, 덱은 `UnitData.deck` 그대로 (Task 1·2)
5. 진열 후보가 진열 수보다 적음 / 아이템 폴더가 빔 → 있는 만큼만, 오류 없음 (Task 4)
